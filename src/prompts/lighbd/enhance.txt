PURPOSE

Fill the supplied character-by-time table sparsely with outfit and hairstyle image tags. The server expands your checkpoints to the right; you do not output the table or repeat unchanged tags at every C anchor. Characters are already resolved. Do not select scenes or change identities.

CONTEXT AND CHRONOLOGY

Use the fixed canonical roster exactly. Read the full source semantically, including who owns or wears each garment, the physical layering order of garments, and the chronology of dressing, removal, replacement and hair arrangement. Preserve established garment identity, color and material when a later mention is shorter. An unclothed narrative state must not acquire default garments.

Saved memory is chronological. Each saved `outfit` or `hair` string is a complete checkpoint for that field. Its latest supplied value, including any user edits, is authoritative immediately before CURRENT. An omitted field inherits its preceding checkpoint; a present empty string clears it. When CURRENT is silent about a garment absent from the latest saved field, do not restore it from older checkpoints, PAST HISTORY, or any selected Profile/lb.extra description, appearance tags or defaults; do not replay past events onto this already resolved starting state. However, CURRENT always supersedes stale saved memory whenever CURRENT explicitly depicts or describes a character wearing, re-wearing, or having changed into garments or a hairstyle/hair arrangement that differs from the saved state—including after a time skip, a new day, or a scene transition. Never change a character's inherent hair color based on lighting, sheen, color casts, atmosphere, figurative prose, or off-card narrative color drift. For legacy prose-only memory, interpret the event chain cumulatively, preserving facts that later events do not supersede.

Only when a field has no saved state, reconstruct it from PAST HISTORY; use selected Profile/lb.extra defaults only if the narrative also leaves that field unknown. Apply changes established in CURRENT to the resulting starting state in source order. Other people and unchanged fields retain their own states.

The source passages and empty table columns share the same Cxxx anchor IDs in chronological order. Record the resulting persistent outfit/hair state at each C anchor boundary, after changes established in that passage. Establish the complete state for every canonical character in the first supplied C anchor, including that passage's changes; then emit only later changed aspects at their own C anchor. Track each person independently, even when absent from a later image. Never move an actual later dressing, removal, or hair-change event into an earlier column. Distinguish an actual mid-scene change from a delayed description of attire the character was already wearing: when a later passage first describes or adds detail to the same unbroken outfit with no intervening dressing or removal event (for example, noting an outer jacket or inner layer already being worn), include those already-worn garments at the anchor where that continuous outfit began—the first supplied C anchor if no earlier change occurred, or the earlier transition anchor that established that outfit—instead of splitting one unchanged outfit at the later description anchor. If several changes occur before one boundary, record the final coherent state there.

SPARSE TAG CHECKPOINTS

Each person has only `outfit` and `hair`, each a comma-separated English image-tag string. `outfit` describes only the complete currently worn wardrobe, accessories and persistent garment arrangement/coverage; `hair` describes the current hairstyle, length, bangs, arrangement and temporary physical hair condition (such as `long hair`, `short hair`, `straight hair`, `blunt bangs`, `ponytail`, `hair bun`, `braid`, `hair down`, `messy hair`, `wet hair`). Hair accessories belong to outfit. Do not include face, expression, pose, camera, background, person-count tags or transient actions. Determine the physically coherent layered state first, then express it as compact established image tags using the established Danbooru vocabulary.

Inherent hair color belongs to the selected Profile (`appearance`/`face_tags`), not to `OUTFIT`. For any character whose selected Profile or baseline already defines hair color, omit hair-color tags (such as `black hair`, `brown hair`, `blonde hair`, `green hair`) from `hair` and drop any inherent or drifted hair-color tag carried over from older saved memory—track only hairstyle, length, bangs, arrangement and physical condition. Include a hair-color tag in `hair` only when CURRENT depicts an explicit hair-color change event (such as actually dyeing or bleaching hair, putting on a colored wig, or a literal physical/magical color transformation), or when no Profile/baseline hair color exists and the narrative states a plain literal color. Never infer or change hair color from lighting reflections, tint/sheen wording (such as a green-tinted sheen, sunset glow, or silvery moonlight), atmospheric mood, or figurative prose.

Keep multi-layer clothing physically coherent and faithful to the source's outer-to-inner layering. When the source describes a garment worn inside or under an outer layer (such as a hoodie layered under an open jacket over a shirt), keep that referenced outer layer in `outfit` alongside the inner layers and preserve the natural layering order; never transfer an "under/inside" relation onto a different garment or invent impossible layering unless the source explicitly depicts an unusual arrangement.

Keep explicit coverage states strictly coherent with worn and displaced garment tags. When a character becomes `nude` or `completely nude`, drop all removed worn garments AND drop stale partial-undress/displacement tags carried over from earlier passages (such as `panties aside`, `panties around one leg`, `skirt lift`, `clothes down`, `open bra`, `strap slip`, `open fly`, `unbuttoned`, `unzipped`, `partially undressed`). When a character becomes `topless`, remove all removed upper-body garments and bras (retaining only explicitly worn open outerwear such as `open jacket` if actually worn); when `bottomless`, remove all removed lower-body garments and underwear; when `no panties` or `no bra`, drop the corresponding underwear tags while keeping still-worn outer garments.

Both fields are required for every person listed in CURRENT CANONICAL CHARACTERS at the first supplied C anchor—never omit any canonical character from the first C anchor, even if they appear only in a later passage or have an empty `{}` baseline (such as a newly introduced NPC). If a character has no saved state, an empty `{}` baseline, and the source does not yet describe their outfit or hairstyle, supply brief context-appropriate baseline tags (for example, `school uniform` or `casual clothes` for `outfit`, and a plain generic style tag such as `medium hair` or `short hair` for `hair`) rather than omitting the character or field. Afterward omit unchanged fields, people and entire C anchors. When a field changes, supply its complete resulting tags, not a delta, action instruction or only the added item. The server replaces that field and copies it rightward until its next explicit checkpoint; outfit and hair propagate independently. Keep all still-worn items when a coat is removed, and remove the coat's worn tags; opening a coat leaves it worn. A removed garment is no longer worn even when held. Never include negative or removal-status tags naming absent garments (such as `jacket removed`, `necktie removed`, `no necktie`, or `without coat`)—simply omit absent garments, and drop any such negative tags if they appear in saved memory. Retain source-established exposure using suitable state tags; do not add garments or concealment. An explicitly empty string clears a field, whereas an omitted field inherits; never use an empty field to mean unchanged or unknown. A windblown braid remains braided; untying it produces a complete loose-hair state. Mere mention, pose or ordinary prop contact creates no checkpoint; a passing mention of one garment (such as a shirt) without a removal event does not remove other still-worn layers.
