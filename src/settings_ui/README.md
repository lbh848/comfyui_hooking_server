# Comfy공방 · 설정

React + TypeScript 설정 화면과 로컬 설정 서버입니다.
초기 설치, 업데이트, Comfy 실행 관리, 모델 관리, 외부 LoRA 관리, 내부 LoRA 관리, 워크플로우 관리, LLM API 관리, 기타 API 관리 화면을 제공합니다.

## 자동 배경 프리셋

**감정 삽화 → 배경 설정 → 자동 배경 모드**는 **배경 설정 → 배경 프리셋 선택 → 툴박스 → 배경** 순서로 표시합니다.
목록은 **배포 프리셋 / 사용자 프리셋**으로 구분하며, 배포 프리셋은 기본 읽기 전용입니다.
**배포 풀기** 후 배포 프리셋을 편집하거나 프리셋 구분을 변경할 수 있고, 잠긴 배포 프리셋도 사용자 프리셋으로 복제할 수 있습니다.
사용자 프리셋과 현재 선택은 설정 파일 옆 `emotion_background_bots.json`, 배포 프리셋은
`src/presets/emotion_background_bots.json`에 저장합니다. 수동 배경 CSS·프리셋 및 캐릭터 봇과는 별도로 관리합니다.
**툴박스 → 세계관 설정** 버튼을 누르면 별도 모달에서 시대·건축·지역 등의 공통 배경 정보를 편집합니다.
**툴박스 → 그리기 설정** 버튼은 현재 선택한 감정 삽화 봇의 기존 그리기 설정 모달을 열고,
**배경 생성 모드**를 먼저 표시합니다. 봇 설정 화면과 같은 값을 편집합니다.
자동 모드에서는 CHARACTER-RESOLVE가 원문과 세계관 설정을 읽고 앵커별 배경을 선택합니다.
배경 카드는 **장소별로 하나씩** 만들며, 같은 장소에서는 시간대·날씨·조명·분위기가 달라져도 재사용합니다.
다른 장소에 대한 카드가 없으면 NPC 카드 예측과 같은 단계에서
**배경 카드 예측**을 실행합니다. 새 이미지는 **배경 LoRA**와 배경 그리기 설정으로 생성하며,
감정 캐릭터 원본은 보관하고 응답 이미지에는 선택한 배경을 합성합니다.
생성된 카드는 **배경** 구간에 표시되며 **배경 새로고침**으로 다시 불러옵니다.
카드 오른쪽 위 **×**로 해당 카드와 이미지를 삭제합니다. 배포 프리셋의 카드는 배포 풀기 후 삭제할 수 있습니다.

## 감정 삽화 합성 설정

**감정 삽화 → 배경 설정 → 자동 배경 모드 → 툴박스 → 합성 설정**에서 캐릭터와 배경을 합성하는 방식을 설정합니다.
**감정 삽화용 봇 → 봇 캐릭터**, **배경 프리셋 → 불러올 배경**에서 이미 등록된 감정 봇 이미지와 배경을 선택합니다. 파일 업로드를 사용하지 않으며, 미리보기 선택은 공방의 현재 봇·배경 선택을 변경하지 않습니다.
위쪽 편집 화면은 배경 전체를 보여주고, **배경에서 보일 영역**을 채움 없는 박스로 겹쳐 표시합니다. **영역 너비 (%)**, **영역 높이 (%)**는 전체 배경 대비 비율입니다. 예시 박스는 드래그로 옮길 수 있지만 실제 생성의 배경 위치는 장면별 예측으로 결정합니다.
**인물 크기 (%)**는 보일 영역 높이 대비 비율이며 1~1,000%로 설정합니다. 입력은 편집 모드와 관계없이 항상 표시됩니다. **인물 크기** 모드의 채움 없는 박스 조절점을 드래그하면 선택한 R/M/L 포인트와 세로 중앙을 유지하며 비율에 맞게 크기를 바꿉니다. 인물 크기는 세 위치에 공통 적용되며 전체 배경 높이보다 크게 확대할 수 있습니다.
예를 들어 보일 영역 높이 50%, 인물 높이 300%이면 인물은 전체 배경 높이의 150%가 됩니다.
**R / M / L 포인트**는 각각의 인물 중심 X좌표를 따로 저장합니다. 포인트를 가로로 드래그하거나 각 수치를 입력합니다. 잘린 배경의 왼쪽이 0%, 오른쪽이 100%이며 기본값은 R 75%, M 50%, L 25%입니다. 세 값은 독립적으로 조절할 수 있고 Y좌표는 잘린 배경의 세로 중앙에 고정됩니다. 포인트에 초점을 두고 좌우 방향키로도 이동할 수 있습니다.
아래 **결과 미리보기**에서 **미리보기 인물 위치**를 R/M/L 중 하나로 선택하고 **랜덤 미리보기**를 누릅니다. 설정한 영역 크기를 유지하면서 배경을 임의 위치에서 자른 뒤, 선택한 포인트의 저장 좌표에 인물을 배치합니다. 포인트 수정은 즉시 반영되고 랜덤 미리보기 자체는 설정을 변경하지 않습니다.
아래 결과는 잘린 배경과 영역 밖으로 나온 인물 전체를 포함합니다. 잘린 배경 밖은 투명하며, 화면의 체크무늬로 투명 여백을 확인합니다. 실제 합성 PNG도 인물을 자르지 않고 같은 투명 여백을 보존합니다. **가이드 숨기기**로 위쪽 테두리와 포인트만 숨길 수 있습니다.
실제 생성에서는 장면별 배경 위치와 `character_position` 코드(R/M/L)를 예측합니다. 합성은 선택된 코드에 대응하는 저장 좌표와 세로 중앙을 사용하며, 같은 장소의 배경 이미지를 재사용해도 장면별 위치 정보는 따로 유지합니다.
**기본값으로 복원**으로 초기 구성을 다시 적용할 수 있습니다. 설정은 자동 배경 모드의 합성에 사용됩니다.

## 로라 프로젝트

**공방 로라 → 에셋**에서 **프로젝트 추가**로 이름·트리거 키워드·설명을 입력해 시작합니다.
에셋 캐릭터 등록 없이 프로젝트를 생성하며, 기존 캐릭터에 연결된 LoRA도 같은 프로젝트 목록에 표시합니다.
**학습용 이미지 / 테스트 이미지 → 파일 업로드**로 PNG·JPEG·WebP를 직접 추가하고,
각 이미지의 **프롬프트 편집**에서 원본과 수정본을 비교하고, **텍스트 / 태그** 방식으로 긍정·부정 프롬프트를 편집합니다.
태그를 삭제하거나 원본 태그를 수정본으로 보내고, **원본으로 되돌리기**로 복원할 수 있습니다.
**블록 태그 규칙**은 일치 태그 표시와 긍정·부정 매칭 전체 삭제를 지원합니다. **LLM 정제**와 **LLM 프롬프트**도 이미지 편집창에서 사용할 수 있으며, 정제 완료 결과는 자동 저장됩니다.
에셋·봇·그림체의 학습용·테스트 이미지가 같은 편집창을 사용합니다. 봇 공통 테스트 이미지는 직접 편집하고, 캐릭터를 적용할 때 **테스트 이미지 일괄 세팅**을 사용합니다.
**이미지 추가**로 에셋 이미지를 가져올 수도 있습니다.
이미지 추가 창은 캐릭터 목록에서 시작하며, **이미지 출처 → 캐릭터 그룹 → 캐릭터 검색** 순서로 대상을 찾습니다.
이미지 출처는 에셋·봇을 지원하고, 봇을 선택하면 캐릭터 그룹 선택이 비활성화됩니다. 에셋에는 배포·사용자 캐릭터가 모두 표시됩니다.
캐릭터 → 대표 이미지가 표시된 복장·표정 폴더 → 이미지 순서로 들어가 선택합니다.
목록은 창 안에서 스크롤되며, 다른 캐릭터로 이동해도 이미지 선택은 유지됩니다.
에셋 LoRA 프로젝트의 학습용 이미지는 원본을 실제 복사한 뒤 태그 분석으로 프롬프트를 채웁니다.
학습용 이미지 화면에 태깅 진행·실패 상태가 표시되며, **선택 태그 분석**으로 다시 실행할 수 있습니다.
테스트 이미지는 태깅 없이 복사합니다. 원본 프롬프트 JSON에서는 학습 모델에 따라 `ANIMA_CONTENT` 또는 `SDXL_CONTENT` 본문만 가져오며, 부정 프롬프트는 비워둡니다. 일반 텍스트 프롬프트는 그대로 가져옵니다.
프로젝트의 **학습 설정**에서는 **학습 프로필 프리셋**을 선택하면 바로 적용·저장됩니다. 학습 설정을 열거나 프리셋 목록을 새로고침하면 현재 선택된 프리셋의 최신 저장값을 다시 적용합니다. 트리거 키워드·설명도 입력 후 자동 저장되며, 상단에서 저장 상태를 확인합니다. 워크플로우·STEP·학습률·옵티마이저 등 상세값은 **학습 프로필 설정 → ANIMA / ILXL / MOSS**에서 편집합니다.
**옵티마이저**에서 **기본값 유지 / AdamW / AdamW8bit / Muon**을 선택하고 **설정 저장**을 누릅니다. **기본값 유지**는 선택한 워크플로우의 설정을 사용하며, 기본 배포 워크플로우는 ANIMA·ILXL에서 AdamW, MOSS에서 AdamW8bit를 사용합니다. 선택한 옵티마이저는 학습 TOML과 실행 기록에도 저장됩니다. Muon은 행렬 가중치를 처리하고 나머지 파라미터에는 AdamW를 사용합니다.
에셋·봇·그림체 프로젝트 상단의 **학습 진행 상황**에는 현재 단계의 진행률·STEP 또는 이미지 수, 경과 시간, 예상 남은 시간이 표시됩니다. STEP 수 옆에는 `1.05초/step` 형식의 평균 학습 속도를 표시합니다. 속도와 학습 예상 남은 시간은 첫 STEP 진행 정보를 기준점으로 삼아, 이후 실제 진행한 STEP 수와 시간으로 계산하므로 모델 로딩·캐시 준비 등 전처리 시간을 제외합니다. 기준점을 받은 뒤 STEP이 진행되기 전이나 준비·대기·테스트 이미지 생성 중에는 학습 속도를 표시하지 않습니다. 예상 시간은 현재 학습 또는 테스트 이미지 생성 단계 기준이며, 계산에 필요한 진행 정보가 없으면 **계산 중**으로 표시합니다. 탭 이동·새로고침 후에도 서버가 계산한 같은 속도를 표시하며, 경과 시간과 완료 후 총 소요 시간은 준비를 포함한 전체 작업 시간입니다.
**복제**는 이미지와 설정을 별도 프로젝트로 복사합니다.

새 프로젝트의 이미지는 `data/lora_data/projects/`에 저장합니다. **학습된 LoRA**에는 프로젝트의 학습 결과를 표시합니다.
학습·큐·결과 관리는 기존 LoRA 엔진을 사용합니다.

## 에셋 그림체 프리셋

**에셋 → 그림체 설정** 상단에서 그림체 전체 조합을 저장하고 선택합니다.
**새 프리셋으로 저장**은 그림 모델 선택, ANIMA·ILXL 아티스트·품질·부정 태그,
생성 옵션, 스타일 LoRA의 **기본값과 적용값을 각각** 저장합니다.
편집 후 **변경 저장**으로 갱신하거나, 새 이름으로 저장해 다른 조합을 만드세요.
**저장값 복원**, **이름 변경**, **삭제**도 지원합니다.

그림체·캐릭터 목록과 항목별 태그 목록은 **배포 그룹 / 사용자 그룹**으로 구분합니다.
기존 항목과 새로 만든 항목은 사용자 그룹에 유지됩니다. 배포 항목은 기본 읽기 전용이며,
복제하면 사용자 항목으로 편집할 수 있습니다. **배포 풀기** 후에는 배포 항목 편집과 그룹 이동이 가능합니다.
배포 파일은 업데이트 시 교체되며 사용자 데이터는 유지됩니다.

이미지 생성과 프롬프트 미리보기에는 **그림체 프리셋 선택이 필수**입니다.
프리셋이 없으면 현재 그림체를 새 프리셋으로 저장하세요. 일괄 생성은 각 슬롯의 그림체 프리셋을
선택하거나 **일괄 설정**에서 한 번에 적용합니다. 이전 체인이나 다른 환경에서 가져온 체인의
프리셋이 없거나 삭제되었으면 다시 선택해야 합니다. 서버도 생성 요청의 프리셋을 검사합니다.

**에셋 일괄 생성**의 각 슬롯 상단에서 **캐릭터 불러오기 / 그림체 불러오기**를 선택하면
저장된 적용값을 함께 불러옵니다. 선택 옆의 **저장값 다시 불러오기**로 같은 항목의 최신 저장값도 다시 적용할 수 있습니다.
**일괄 설정**에서도 두 항목을 불러와 **전체 슬롯에 적용**할 수 있습니다.
일괄 설정의 드롭다운에서 **적용 안 함**을 선택하면 해당 항목과 연결된 태그는 슬롯별 기존 값을 유지합니다.
캐릭터·그림체 불러오기에서 선택하면 해당 구역의 불러온 설정 전체를 적용 대상에서 제외합니다.
기본으로 켜진 **슬롯별 표정·구도 유지**는 슬롯마다 지정한 표정·구도를 보존하며, 해제하면 해당 값도 함께 적용합니다.
불러온 값은 슬롯에서 추가 편집하고 체인 프리셋으로 저장해 재사용할 수 있습니다.

상단 **체인 프리셋**에서 항목을 선택하면 **체인 프리셋 불러오기** 모달이 열립니다.
이름·그룹·슬롯 수·반복 횟수를 확인하고 **불러오기**를 누르면 현재 체인을 교체합니다.
현재 슬롯이 있으면 **이어붙이기**로 뒤에 추가할 수 있으며, **취소**하면 현재 선택과 체인을 유지합니다.
같은 프리셋을 다시 선택해도 확인 모달이 열립니다. 불러오기에 실패하면 모달 안에서 오류를 확인하고 다시 시도할 수 있습니다.

체인 슬롯은 화살표로 생성 순서를 표시합니다. PC에서는 두 열을 오가며 이어지고, 좁은 화면에서는 위에서 아래로 이어집니다.
불러오기 선택란 아래의 **DIFF**는 직전 슬롯과 다른 캐릭터·그림체·그림 모델·태그 프리셋을 **이전 값 → 현재 값**으로 보여줍니다.
슬롯을 이동하거나 삭제하면 비교 대상도 즉시 바뀝니다. 첫 슬롯은 비교 대상이 없으며, 같은 프리셋은 차이 목록에서 제외합니다.
상세 설정은 **그림체 설정 / 캐릭터 설정**으로 나누어 펼칠 수 있고, 일괄 생성에서는 **태그 편집** 버튼을 표시하지 않습니다.

그림체를 선택하면 두 열의 저장값을 함께 불러오며 캐릭터·참조 이미지·캐릭터 LoRA와 체인 슬롯은 유지합니다.
프리셋을 삭제해도 현재 적용값은 유지됩니다. 그림 모델은 선택한 프리셋의 ID로 참조하므로
모델·워크플로우·샘플링의 내용은 **그림 모델 설정**에서 관리합니다.
사용자 그림체는 `config/asset_style_presets.json`, 사용자 캐릭터는 `data/asset_data/tags.json`에 저장합니다.
배포 그림체·캐릭터는 각각 `src/presets/asset_style_presets.json`, `src/presets/asset_character_presets.json`에 저장합니다.
현재 선택과 편집 중인 값은 기존 브라우저 초안에 보관합니다.
다른 창에서 목록이 변경된 경우 덮어쓰기를 막고 새로고침을 안내합니다.

## 에셋 마스크 기반 생성

**에셋 생성 → 마스크 기반 생성**에서 캐릭터 영역을 1~3개 만들고 빈 캔버스에 사각형을 드래그합니다.
선택한 영역을 다시 드래그하거나 X·Y·너비·높이(%)로 조절할 수 있습니다.
각 영역의 외모·복장·표정·자연어와 캐릭터 LoRA·참조 이미지는 해당 캐릭터에 연결되고, 그림체·배경·구도는 공통으로 사용합니다.
첫 번째 영역의 참조 강도·모드와 현재 이미지 크기·생성 옵션을 함께 사용하며, 결과는 첫 번째 영역의 출력 폴더에 저장합니다.

브라우저는 정규화된 박스 좌표와 캐릭터별 프롬프트를 `prompt_json.fields.MULTI_CHAR.layout`과 `MULTI_CHAR`에 담아 일반 `asset/preview`, `asset/enqueue`로 전송합니다.
서버는 좌표를 검증하고 캐릭터 순서와 프롬프트를 함께 정렬해 RGB 마스크를 생성합니다. PNG는 `assets`에 포함되고 `REGION_MASK`가 이를 참조합니다.
이 JSON이 `asset_generation` 큐를 거쳐 워크플로우의 긍정프롬프트 입력과 Soya 1st sampler로 전달됩니다.
**프롬프트 미리보기**에서 서버가 조립한 최종 프롬프트와 좌표를 확인할 수 있습니다. 서버 코드 업데이트 후에는 프로그램을 재시작하세요.

## 삽화 생성 설정

**삽화 프롬프트 설정 → 특수 전략 → 로컬 LLM 대응 전략**에서 다음 두 기능을 각각 켜고 끕니다.
기본값은 모두 꺼짐이며 변경 즉시 자동 저장됩니다.

- **생성이 끝나면, 공방-LLM 로드**: 삽화 작업이 끝나면, LLM 모델을 GPU에 올립니다.
- **DETAIL이 시작할 때 그림 모델 로드**: detail이 시작하는 시점에서 그림 모델을 미리 GPU에 올립니다.
  초기 웜업 시간을 LLM 생성 시간에 가릴 수 있습니다.
  **주의: DETAIL을 로컬 LLM으로 처리 중이라면 사용하지 마세요**

그림 모델 미리 로드는 로컬 Comfy의 현재 작업 프리셋을 사용하며, DETAIL 배치가 여러 개여도 작업당 한 번만 실행합니다.
공방-LLM 로드는 이미지 생성과 후처리가 끝난 뒤 실행합니다. 미리 로드에 실패해도 생성 결과는 유지하며 프로그램 로그에 원인을 기록합니다.

**삽화용 봇 설정 → 매칭 기반 규칙 → 단어 기반 규칙** 맨 위의 **가중치 클램프**는 삭제하거나 이동할 수 없는 고정 항목입니다.
봇마다 **사용 ON**, **클램프 수치 1.1**로 시작하며, 사용 여부와 수치(0.1~5)만 바꿀 수 있습니다.
**규칙 저장**으로 저장합니다. 조립 전 LLM이 만든 SETUP·CHAR·SUPPLEMENT와 부정 태그의 가중치를 지정한 수치의 양수·음수 범위 안으로 제한합니다.
다인 그림의 배경·구도·캐릭터별 LLM 결과에도 적용하며, 이후 단어 규칙과 그리기 설정에서 지정한 가중치, 이미 조립된 프롬프트는 그대로 유지합니다.

**그리기 설정**은 **일반 삽화 생성 모드 / 캐릭터 자동 생성 모드** 내부 탭으로 나뉩니다.
두 탭은 같은 항목을 제공하며, 봇별 설정값을 모드마다 별도로 자동 저장합니다.
기존 설정은 일반 삽화 생성 모드에 유지되고, 캐릭터 자동 생성 모드는 기본값으로 시작합니다.
각 모드 안에서 프리셋·레퍼런스·보정은 공통이며, 일반 삽화의 이미지 크기·시드는 **1인 / 2인 이상**으로 나뉩니다. 캐릭터 자동 생성의 크기·시드는 인원수와 관계없이 공통입니다.
이미지 크기·시드 복사는 현재 모드 안에서만 적용됩니다. 선택한 프리셋의 태그 자체를 편집하면 그 프리셋을 사용하는 다른 설정에도 반영됩니다.
서버에 모드별 저장 기능이 아직 반영되지 않았다면 프로그램 재시작 안내를 표시합니다.

각 모드 상단의 **그리기 설정 프리셋**에서 프롬프트 프리셋 선택·레퍼런스·보정·크기·시드를 한 묶음으로 저장하고 불러옵니다.
**현재 설정 새로 저장**, **불러오기**, **덮어쓰기**, **삭제**를 지원하며, 같은 모드의 프리셋을 다른 봇에서도 재사용할 수 있습니다.
일반 삽화 프리셋에는 1인·2인 이상 크기와 시드가 각각 포함됩니다. 불러온 설정은 현재 봇의 선택한 모드에만 자동 저장됩니다.
프리셋을 덮어쓰거나 삭제해도 이미 봇에 적용된 설정은 유지됩니다. 읽기 전용 봇에서도 새 프리셋 저장은 가능합니다.
사용자 프리셋은 `config/illustration_generation_presets.json`에 저장되어 재시작 후에도 유지됩니다.

**그리기 설정 → 프롬프트 프리셋**에서 선택한 아티스트·품질·배경·부정 프리셋을 사용합니다.
일반 삽화 생성 모드와 캐릭터 자동 생성 모드 모두 ANIMA·ILXL 배경 프리셋을 각각 선택하고 태그를 편집할 수 있습니다.
**없음**은 해당 태그를 추가하지 않습니다. 선택한 프리셋을 찾을 수 없으면 오류를 표시합니다.

**삽화 백업 → 수동 그리기**에서 **1인 / 2인 / 3인**을 선택하면 해당 인원만큼 캐릭터 선택 칸을 표시합니다.
각 캐릭터의 프로필 카드는 좌우 화살표로 넘기며, 카드 이름과 현재 번호 / 전체 개수를 함께 표시합니다.
대표 이미지를 누르면 확대합니다. 카드가 한 장이면 화살표는 비활성화됩니다.
**상황**은 **LLM에게 맡겨본다 / 직접 입력** 중 선택합니다.
**후처리 테스트**를 켜면 현재 봇의 대사 합성 설정을 이번 그림에 적용하며, 대사도 자동 생성하거나 직접 입력할 수 있습니다.
하단 **그리기** 버튼은 스크롤과 관계없이 유지됩니다. 완료된 이미지는 **삽화 백업**에서 확인합니다.
**백그라운드**로 보낸 창은 **수동 그리기** 버튼을 다시 누르면 입력 내용 그대로 열립니다.
같은 탭에서 새로고침해도 창을 백그라운드에 복구하며, 인원·캐릭터·프로필 카드·상황·후처리 대사를 유지합니다.
다른 메뉴나 설정 작업 공간에서 새로고침한 경우에도 **백그라운드 작업**에서 다시 열 수 있습니다.
**닫기**로 창을 닫으면 보관한 입력 내용을 지웁니다.

**삽화 백업 → 최근 세션 다시 그리기**는 최근 흐름 임시 그룹(최대 8개) 중 한 세션을 골라,
그 세션에 포함된 모든 이미지를 다시 그립니다.
각 이미지의 **LLM 생성 태그**만 재사용하고, 사용자 프리셋 태그·LoRA·그림체·부정 프롬프트·샘플링 같은
나머지 값은 현재 **삽화용 봇 설정**과 **그림 모델 설정**에서 새로 읽어 서버 빌더로 다시 조립합니다.
태그 생성 LLM을 다시 호출하지 않으므로 추가 API 비용은 들지 않습니다.
현재 그림 모델과 같은 계열(ANIMA/MOSS)의 세션만 대상으로 하며, 계열 간 변환은 하지 않습니다.

**삽화용 봇 설정 → 툴박스 → 삽화 데이터 준비**에서 원클릭 설정을 엽니다.
캐릭터 선택 → 기능 선택 → 세부 설정 → 최종 확인 순서로 진행하며, 대표 이미지가 저장된 캐릭터만 선택합니다.
태그 분석, 태그 필터링, 외모·복장 일괄 정제, 부정 프롬프트 적용, 데이터 패치, 얼굴 태그 분석, 얼굴 부정 태그 적용,
LLM 얼굴/눈 태그 정제, 얼굴 태그 필터링 중 사용할 기능을 골라 순서대로 실행합니다.
얼굴 태그 분석과 얼굴 부정 태그 적용은 각각 선택·실행하며, 진행률과 성공 개수를 따로 표시합니다.
얼굴 태그 분석만 실행할 때는 부정 태그를 입력하지 않아도 됩니다.
외모·복장 정제는 대표 이미지 처리 뒤, 데이터 패치와 얼굴 처리 전에 실행합니다.
대표 이미지가 있는 프로필만 대상으로 하며, 캐릭터·카드별 일괄 잠금을 반영하고 정제 결과를 카드에 자동 저장합니다.
기존 공통 정제 프롬프트를 사용하며, 단계별 설정에서 FACE 이미지 없이 이 작업만 실행할 수도 있습니다.
부정 프리셋·FACE 크롭·저장된 필터 프로필을 지정하고, FACE가 없거나 대표 이미지가 달라진 캐릭터를 모아 선택할 수 있습니다.
진행 화면은 단계별 결과와 실패 항목을 표시합니다. 백그라운드로 보내도 실행은 계속되고,
안전 중단은 현재 작업을 마무리한 뒤 이 실행의 대기 작업과 나머지 단계를 취소합니다.

**삽화용 봇 설정 → 툴박스 → 로라 일괄 적용**에서 **캐릭터 LoRA / 얼굴 LoRA**를 프로필 카드별로 적용합니다.
이름·설정 상태·강도로 대상을 찾고, **현재 봇 학습 프로젝트**의 대표 LoRA를 자동 매칭하거나 **직접 선택**합니다.
**기존에 추가 / 선택한 LoRA로 교체 / LoRA 일괄 해제**를 고른 뒤, 변경 내용을 확인하고 저장합니다.
추가 시 같은 경로의 LoRA는 중복하지 않고 강도를 갱신합니다. 강도가 달라지면 일괄 적용 버튼이 활성화됩니다.
교체할 후보가 없는 카드는 기존 설정을 유지합니다.
대상 선택 화면의 **선택한 카드 LoRA 일괄 해제**로도 바로 변경 내용을 확인할 수 있습니다.
선택한 종류(캐릭터 또는 얼굴)의 LoRA만 해제하며, **확인 후 일괄 해제**를 눌러 저장합니다.

**삽화용 봇 설정 → 캐릭터** 옆의 보기 모드에서 **상세 보기 / 간략 보기**를 선택합니다.
간략 보기는 캐릭터를 2열로 배치하며, 좁은 화면에서는 1열로 표시합니다.
대표 이미지 옆에서 성별, 선택 기준, 얼굴 이미지·얼굴 태그, 외모·기본 복장,
얼굴·캐릭터·스타일 LoRA와 각 강도, 데이터 패치 상태를 확인합니다.
태깅은 대표 이미지에 저장된 프롬프트 개수로 표시하며, 패치 상태는 프로필별 파일 존재 여부를 확인합니다.
하단의 **프로필 현재 번호 / 전체 개수**와 좌우 화살표로 프로필을 순환합니다.
카드의 **상세 보기**는 해당 캐릭터의 기존 편집 화면을 새 모달로 열며, 목록의 보기 모드를 유지합니다.
간략 보기와 상세 보기의 카드 오른쪽 위 **X**로 캐릭터 삭제 확인창을 엽니다.
삽화용 봇 설정과 감정 삽화용 봇 설정의 생성된 캐릭터는 **생성됨 · 남은 수명** 왼쪽의 **수명 갱신**으로 남은 수명을 설정된 최대 횟수로 되돌립니다.
**삭제 확인**을 누르면 해당 캐릭터의 정보와 이미지가 삭제되고 목록이 갱신됩니다. **취소**하면 유지됩니다.

**캐릭터 태그 일괄 관리**는 캐릭터 → 프로필 카드 → 얼굴·눈·외모·기본 복장 트리로 표시합니다.
캐릭터와 태그 그룹을 접거나 펼치고, 이름·카드·별칭·태그로 검색할 수 있습니다.
캐릭터마다 왼쪽에 카드 하나를 두고 화살표로 프로필을 순환합니다. 오른쪽에는 모든 프로필과 개별 잠금을
연결선으로 표시하며, 프로필을 누르면 왼쪽 선택도 바뀝니다. **통합 태그 편집**과 **캐릭터 상세**는
현재 선택한 프로필로 열립니다. 왼쪽 일괄 잠금은 해당 캐릭터의 모든 프로필을 정제에서 제외합니다.
잠금은 자동 저장되며, 정제 버튼에는 제외 설정을 반영한 대상 카드 수를 표시합니다.
**얼굴·눈 일괄 자동 분류**와 **외모·복장 일괄 정제**에서 실행할 카드를 선택합니다.
각 작업의 프롬프트를 따로 설정하며, 캐릭터·프로필 잠금은 두 작업 모두에 적용합니다.
얼굴·눈 분류는 카드별 얼굴 이미지와 대표 이미지 프롬프트를 사용하고 결과를 외모에도 동기화합니다.
카드별 완료·실패를 표시하며 중단하면 다음 카드로 진행하지 않습니다.

**얼굴·눈·절대·부정**과 **외모·기본 복장**은 기존 테스트 서버의 태그 편집 흐름을 사용합니다.
이미지 옆에서 메인 대표 프롬프트의 원본 태그와 편집본을 비교하고, 클릭·드래그·텍스트 입력으로 수정합니다.
성별 태그는 고정하며 태그 설명, 중복 제거, 자동완성을 지원합니다. 대표 프롬프트가 없으면 저장된 카드 태그를 표시합니다.
개별 태그 편집과 일괄 관리에서 **태그 설명**을 끄면 마우스 호버·키보드 포커스 시 툴팁을 표시하지 않으며, 열려 있던 툴팁도 닫습니다.
얼굴 모달은 카드별 얼굴 이미지, LLM 얼굴·눈 자동 분류, 캐릭터 부정 태그와 이미지 이름 태그를 제공합니다.
저장 시 성별·얼굴·눈·절대 태그를 합쳐 해당 카드의 외모에도 반영합니다. 캐릭터 부정 태그는 DETAIL 제외 특징이며 부정 프롬프트가 아닙니다.
외모·복장 모달은 대표 이미지 전환, LLM 정제, 현재 편집값으로 자동 그리기, 최근 8개 내역의 편집값 불러오기를 제공합니다.
두 모달 모두 **카드에 저장**으로 적용하며 다른 프로필·LoRA 등 편집하지 않은 설정을 유지합니다.
LLM 프롬프트는 글로벌 읽기 전용/PC 커스텀 편집 및 현재 원본 태그로 변수 치환 미리보기를 지원합니다.
모달을 닫아도 편집 중인 내용은 유지되며, **캐릭터 카드 저장**으로 저장합니다.

**삽화 → 삽화 프롬프트 설정 → 생성 설정**은 **파이프라인**, **에셋 선택**,
**삽화·만화 장면 선택**, **PLAN·DETAIL**, **POST PROCESS**, **최종 프롬프트** 탭으로 나눕니다.
넓은 화면에서는 왼쪽 카테고리와 오른쪽 설정 영역을 나누고, 항목 설명과 입력칸을 행별로 정렬합니다.
파이프라인에서는 KEYVIS·캐릭터 마스크·비주얼 교정을 묶고 세부 옵션을 들여쓰기로 구분합니다.
삽화와 만화의 장면 설정, PLAN과 DETAIL의 병렬 처리·느린 요청 재시도도 각각 구분합니다.
상위 기능을 끄면 관련 세부 옵션은 값을 유지한 채 비활성화됩니다.
공통 대사 합성 설정과 미리보기는 **POST PROCESS** 탭에서 사용합니다.
**자막 / 텍스트 교체**별로 배치, 글자, 색상 등 관련 옵션을 묶어 표시합니다.
**글자 크기** 그룹에는 글자 크기와 바로 아래의 최소 글자 크기를 표시합니다.
텍스트 교체의 **자동 추론**을 켜면 두 크기 입력을 숨기고, 감지된 영역과 대사 길이에 맞춰 크기를 정합니다.
자동 추론을 끄면 기존 수동 크기가 다시 표시됩니다. 텍스트 교체 결과는 가로 배율·자간·외곽선까지 포함해 영역 안에 맞춥니다.
텍스트 교체는 실제 글자 잉크에 맞춰 좌우 빈 여백을 줄이며, 밝은 말풍선의 내부 경계가 확인되면 테두리를 보존하고 그 안에 글자 전체를 맞춥니다.
이전에 대사창·말풍선을 선택했다면 자막 설정이 열리며, **합성 설정 저장**으로 새 합성 방식을 적용합니다.
합성 결과는 설정 옆에 항상 표시하며 옵션·대사 변경 후 자동 갱신합니다. 좁은 화면에서는 미리보기를 위에 배치합니다.
삽화 백업의 합성 전 원본이나 업로드한 이미지를 배경으로 사용할 수 있으며, 이미지를 누르면 원본 크기로 확인합니다.

생성 설정은 별도 저장 버튼 없이 자동 저장합니다. 토글·선택은 변경 즉시,
숫자·텍스트는 입력을 멈춘 뒤 600ms 후 또는 입력칸을 벗어날 때 저장합니다.
**저장 대기 중…**, **저장 중…**, **자동 저장됨**으로 상태를 표시하며,
빈 숫자나 최소·최대가 뒤집힌 범위는 저장하지 않고 오류를 표시합니다.
저장 중에도 편집할 수 있고 후속 변경은 순서대로 저장합니다. 실패하면 입력을 유지하고 **자동 저장 다시 시도**를 제공합니다.
공통 대사 합성 설정은 **합성 설정 저장** 버튼으로 별도 저장합니다. 미리보기만으로 설정이 저장되지는 않습니다.

**삽화 백업** 카드는 큰 썸네일 아래에 봇 이름, 생성 방식, 생성 시각, 파일명, 생성 시간을 표시합니다.
이미지를 누르면 이미지 전용 라이트 뷰어로 확대하며, 닫기 버튼이나 Escape로 돌아옵니다.
카드의 **재생성**, **수정**, **예약**, **이미지 분석**, **LLM 흐름**, **다운로드**, **삭제**와 **프롬프트 펼치기**를 사용합니다.
**예약**은 다음 요청에 이 이미지를 재전송하도록 지정하며, **예약됨**을 다시 누르면 취소됩니다. 다른 이미지를 예약하면 기존 예약이 바뀝니다.
**이미지 분석**의 **모순점 찾기**는 최대 시험 횟수만큼 단어 규칙을 바꿔 재생성·검수하고, **질문**은 이미지와 생성 프롬프트에 대한 답변을 제공합니다.
분석 중 **중지**할 수 있으며, 개선이 확인된 규칙은 검토·수정한 뒤 **이 규칙만 추가**로 해당 봇에 저장합니다.
JSON 워크플로우로 새로 생성한 삽화는 JSON 빌더가 완성한 실제 전달 데이터를 **최종 JSON**으로 표시합니다.
**생성 로그**, **삽화 흐름**의 이미지 생성 상세, 백업 상세에서 같은 결과를 확인하고 **JSON 다운로드**로 받을 수 있습니다.
첨부 데이터는 **첨부 데이터 (assets)**를 펼쳐 확인합니다. 최종 JSON 기록이 없는 이전 백업은 저장된 프롬프트를 표시합니다.

**삽화 수정**은 **생성 태그 / 사용자 사전 태그 / 조립된 프롬프트 / 최종 JSON** 탭으로 나눕니다.
**생성 태그**에는 장면에 맞춰 구성한 배경·구도·캐릭터별 태그와 얼굴 표현을,
**사용자 사전 태그**에는 품질·아티스트·부정 프롬프트, LoRA 트리거, 캐릭터 카드의 얼굴·눈 태그를 표시합니다.
LoRA 설정에 보관된 트리거 원문은 참고용으로 표시하고, 실제 적용된 태그는 영역별 트리거 또는 조립된 프롬프트에서 수정합니다.
생성된 캐릭터 태그에는 프로필의 외모가 포함될 수 있으며, 출처가 따로 남지 않은 전체 장면·영역 공통 태그는 **조립된 프롬프트**에 표시합니다.
각 블록과 최종 JSON은 같은 편집값을 사용하며, **편하게 수정** 결과도 모든 탭에 반영됩니다.
이번 그림의 저장된 태그만 수정하며 원래 프리셋·캐릭터 카드는 바꾸지 않습니다. 영역별 태그와 전체 장면은 각각 편집합니다.
JSON 형식 오류가 있으면 **최종 JSON**에서 수정한 뒤 태그 편집과 다시 그리기를 계속할 수 있습니다.

**생성 로그**는 CONTEXT, Raw 프롬프트, 치환 후 Raw 프롬프트, 파싱 결과,
단어 기반 규칙 결과, CHAR_LIST 획득 결과, 최종 프롬프트를 처리 순서대로 표시합니다.
**이전 / 다음**으로 기록을 한 건씩 확인합니다.

**채팅 히스토리**는 글자수 설정, 검색, 저장 기록 목록을 함께 표시합니다.
**보기**를 누르면 요약 정보와 접힌 상세 항목이 열립니다. 원문 CHAT 메시지,
캐릭터 프로필·복장·머리 상태 편집, 단계별 결과, 리롤 보관 기록을 각각 펼칠 수 있습니다.
다음 대화의 저장 상태와 현재 장면 재생성의 시작 상태를 구분하며,
프로필 시간표에서 직접 판정한 값과 이전 구간에서 이어받은 값을 확인할 수 있습니다.

**프롬프트 구성**은 전체 조립 흐름에서 단계를 선택해 ON/OFF·실행 조건,
조립 재료와 입력 변수, 블록별 출처·내용, SYSTEM·USER 메시지와 결과를 확인합니다.
파란 배경으로 바뀌는 입력·설정을 구분하며 **지침 모드**에서 다른 구성을 비교할 수 있습니다.
비교 모드 선택은 실제 생성 설정을 바꾸지 않습니다.

**지침 편집**은 처음에는 접힌 블록으로 표시하며 제목을 눌러 전체 편집 영역을 펼칩니다. 접어도 편집값을 유지하고, 미저장 변경 개수는 접힌 제목에서도 확인할 수 있습니다.
CHARACTER-RESOLVE, KEYVIS, POST PROCESS, 공유 프롬프트,
출력 템플릿 등 실행 단계별 그룹으로 나뉩니다. 각 지침의 제목에는 `call2_keyvis`,
`call2_job`, `call2_common`, `call2_preset`처럼 실제 조회·저장 키를 표시합니다.
그룹 안의 지침을 각각 펼쳐 편집하며, 그룹을 바꿔도 편집값이 유지됩니다.
**지침 저장**은 변경한 키만 전송하고 서버가 저장했다고 반환한 키만 저장 완료로 처리합니다.
**지침 다시 불러오기**는 저장된 내용을 읽으며, 미저장 변경이 있으면 버릴지 확인합니다.

**노드·Think 확인**은 실행 단계를 연결선과 작업 묶음으로 보여줍니다.
노드를 누르면 연결된 경로를 강조하고 입력·출력, 실행 조건, 메인·폴백 연결과 검사 결과를 표시합니다.
노드가 많은 작업 묶음은 접어서 표시하며 제목을 눌러 펼칩니다. 좁은 화면에서는 단계가 아래로 이어집니다.
**모두 확인**은 현재 흐름에서 사용하는 연결을 번호순으로 한 번씩 검사하며 **검사 중지**로 멈출 수 있습니다.
노드 배지는 메인·폴백 Think 미사용(초록), 폴백 Think 사용(노랑), 메인 Think 또는 연결 문제(빨강),
미검사·재검사(회색)를 구분합니다. 빨간 배지는 **폴백 미설정**, **메인·폴백 동일**, **메인 검사 실패**처럼 원인을 바로 표시하며, 여러 원인이 있으면 함께 표시합니다. 추론 정보가 없는 응답은 원본과 같이 Think 미사용으로 취급합니다.
모델·추론 옵션 등 연결 설정이 바뀌면 이전 결과는 재검사 대상으로 표시합니다.
탭 복귀, 창 복귀, **흐름 새로고침**, 검사 시작 시 저장된 연결을 다시 확인합니다.

## 삽화 그림 모델 설정

**삽화 → 그림 모델 설정**의 **그림 모델 선택**, **워크플로우 선택**과
**모델**, **공통 LoRA**, **샘플링**, **JSON** 탭의 변경 사항은 입력이 멈춘 뒤 600ms 후 자동 저장됩니다.
**저장 대기 중…**, **저장 중…**, **자동 저장됨**으로 진행 상태를 표시하며 다음 생성부터 적용됩니다.
빈 숫자나 올바르지 않은 JSON은 저장하지 않습니다. 저장 실패 시 입력을 유지하고
**자동 저장 다시 시도** 또는 **저장된 설정 다시 불러오기**를 제공합니다.
**저장 전 변경 취소**는 아직 저장하지 않은 변경만 되돌립니다.

**공통 LoRA**의 불러온 항목과 **LoRA 추가** 목록은 이름 옆에 `페이지` 링크를 표시합니다.
클릭하면 해당 Civitai 모델·버전 페이지 또는 Hugging Face 저장소를 새 탭에서 엽니다.
출처 페이지를 확인할 수 없는 LoRA에는 링크를 표시하지 않습니다.

## 내부 LoRA 관리

**리소스 관리 → 내부 LoRA 관리**에서 **에셋**, **봇**, **그림체**를 선택합니다.
에셋은 등록된 캐릭터를, 봇은 등록된 봇을 먼저 선택한 뒤 해당 대상의 학습 프로젝트를 관리합니다.
**프로젝트 추가**는 캐릭터·봇을 선택한 다음 화면에 표시됩니다. 그림체는 프로젝트 목록에서 시작합니다.
프로젝트 생성·복제·삭제, 학습용·테스트 이미지 추가와 프롬프트 편집, LLM 정제,
학습 설정·실행, 세션·STEP·미리보기·Loss·대표 LoRA 관리를 제공합니다.
봇은 캐릭터 카드별 학습과 다른 프로젝트에서 가져오기, 공통 테스트 이미지 세팅,
자동 피드백을 지원합니다. 그림체는 ANIMA·SDXL별 설정, 파일 업로드, 태그 분석과 이미지 필터링을 지원합니다.
봇 프로젝트 이름 옆의 **모든 캐릭터 잠금 / 모든 캐릭터 해제**는 검색으로 숨겨진 카드를 포함한 전체 카드의 순차 학습 스킵을 설정·해제합니다.
캐릭터 이름과 카드 개수 옆의 **모든 카드 잠금 / 모든 카드 해제**는 해당 캐릭터에만 적용됩니다. 각 카드의 **순차 학습 스킵** 슬라이드 토글로 개별 조정할 수 있습니다.
**학습 경로 설정**에서 LoRA 폴더, ComfyUI 입력 폴더와 학습 워크플로우를 지정합니다.
학습·정제 작업의 상태와 취소·일시 정지·재개는 **작업 내역 관리 → 작업 큐**에서 확인합니다.

## 모달 백그라운드 보관

작업 모달 오른쪽 위의 **백그라운드**를 누르면 화면 하단 **백그라운드 작업**에 탭으로 보관됩니다.
다른 메뉴로 이동해도 입력 내용과 진행 중인 작업을 유지하며, 탭을 누르면 원래 메뉴와 모달을 다시 엽니다.
상단 작업 공간 전환으로 **설정 ↔ 삽화**를 오가도 목록과 실행 상태가 유지됩니다.
각 탭에 작업 공간과 메뉴를 표시하며, 다른 작업 공간의 탭을 누르면 해당 화면으로 전환해 모달을 다시 엽니다.
여러 모달을 함께 보관할 수 있고, 좁은 화면에서는 탭을 가로로 넘겨 선택합니다.
탭에 포커스가 있을 때 좌우 방향키와 Home/End로 이동하고 Enter로 다시 열 수 있습니다.

작업 중인 탭에는 일렁이는 불꽃과 **작업 중**, 작업하지 않는 탭에는 **보관 중**이 표시됩니다.
완료하거나 중단하면 불꽃이 꺼집니다. 시스템에서 동작 줄이기를 설정하면 불꽃을 정지된 모습으로 표시합니다.
보관 상태는 현재 열린 화면에서 유지되며, 브라우저 새로고침이나 창 닫기 후에는 복원하지 않습니다.

## LLM 로그

사이드바의 **작업 내역 관리**에는 **작업 큐**의 대기 개수와 **LLM 로그**의 동시 실행 개수가 표시됩니다.
다른 페이지를 보는 중에도 2초 간격으로 갱신되며, 조회에 실패하면 숫자 대신 **—**를 표시합니다.

**작업 내역 관리 → LLM 로그**에서 **로그 이력**과 **라이브**를 함께 확인합니다.
넓은 화면에서는 좌우로, 좁은 화면에서는 위아래로 표시합니다.
이력은 최신순으로 자동 갱신되며 작업·모델·출력 요약 검색, 상태·LLM 슬롯 필터를 제공합니다.
로그를 선택하면 같은 화면 아래에서 입력 전체, 출력 전체, 오류 내용, 토큰·시간 통계와 전체 기록을 확인하고 복사할 수 있습니다.
원본 작업 로그와 설정 화면의 LLM 테스트·프리셋 분류 기록을 함께 표시합니다.

라이브는 활성 스트림의 출력·추론 내용과 통계를 갱신하며 **재시도**, **병렬로 재시도**,
**현재 내용 사용**, **중지**를 제공합니다. 완료된 스트림은 라이브에서 사라집니다.
진행 중인 요청이 생기면 라이브가 자동으로 펼쳐지며, 각 요청의 제어 버튼은 위쪽에 표시됩니다.
추론·출력 내용은 기본으로 접혀 있고, 버튼 아래의 **내용 펼치기**·**내용 접기**로 확인할 수 있습니다.
응답 중 토큰 수와 평균 속도는 수신한 텍스트 기준의 추정값이며, 완료 시 제공된 사용량을 표시합니다.
Gemma의 추론 텍스트는 로그 상세의 **추론 내용**에서 확인합니다. 완료된 출력 토큰과 속도는 추론 및 최종 답변을 포함한 서버 사용량입니다.
**공방-로컬 LLM (추론)**은 추론 한도를 **1,024 / 2,048 / 4,096토큰** 중 선택하며 기본값은 **2,048토큰**입니다.
**공방-로컬 LLM (비추론)**은 같은 모델에서 추론을 끈 연결입니다.
두 연결의 컨텍스트 기본값은 **32K(32,768토큰)**이며, **8K~256K** 범위에서 **8K 단위**로 변경할 수 있습니다.
**자동 스크롤**을 켜도 위로 스크롤해 읽는 동안은 위치를 유지하고, 맨 아래로 돌아오면 다시 따라갑니다.
연결이 끊어지면 재연결 상태를 표시하고 자동으로 복구합니다.

## 메모장

**작업 내역 관리 → 메모장**에서 작업 중 임시로 기억할 내용을 자유롭게 적습니다.
입력한 내용은 자동으로 저장되며 설정·삽화·에셋·로라 화면에서 같은 메모를 확인합니다.
프로그램을 다시 시작해도 내용이 유지됩니다.

## 프리셋 관리

**리소스 관리 → 프리셋 관리**에서 **프리셋 편집**, **숨김 관리**,
**SD studio 프리셋 임포트**를 사용합니다.
프리셋 이름·내용 검색, 태그 비교, 에셋 사용 추적, 활성·숨김 항목의 일괄 이동을 지원합니다.
**아티스트 프리셋** 오른쪽의 **배경 프리셋**에서 배경 태그를 별도로 관리합니다.
이름만 입력해 빈 프리셋을 저장하거나 기존 프리셋의 태그·텍스트를 모두 비워 저장할 수 있습니다.
태그 입력 중에는 원본의 `src/auto_complete` CSV 검색으로 추천 태그와 한국어 설명을 표시합니다.
추천 목록은 입력란 위나 아래에 떠서 표시되며 페이지나 저장 버튼을 밀지 않습니다.
두 글자부터 영문 태그·한글 키워드를 검색하며, 클릭 또는 방향키와 Enter/Tab으로 현재 태그를 완성합니다.
추천은 Esc나 닫기 버튼으로 닫습니다. SD studio 프리셋 임포트의 태그 편집에서도 같은 기능을 사용합니다.
숨김 관리는 **활성 프리셋 / 숨긴 프리셋**을 나누어 표시합니다. 각 항목에서 바로 숨기거나
복원할 수 있고, 검색 결과의 전체 선택과 선택 개수 표시로 여러 항목을 한 번에 정리할 수 있습니다.
캐릭터와 체인 프리셋도 같은 방식으로 관리합니다. 편집 화면의 구분·상태 필터는 숨김 관리에 적용되지 않습니다.
**프리셋 편집 → 프리셋 삭제**, 숨김 관리의 항목별 **삭제** 또는 **선택 삭제**로 비배포 프리셋을
삭제할 수 있습니다. 확인 창에 삭제할 이름·상태·개수를 표시하며, 삭제 후에는 숨김 관리에서 복원할 수 없습니다.
프리셋 삭제는 생성된 이미지나 에셋 파일을 삭제하지 않습니다. 삭제한 프리셋을 참조하는 설정은 다시 선택해야 할 수 있습니다.

**배포자료 (읽기전용)**는 `src/presets/presets.json`, **비배포 (편집가능)**는
`data/asset_data/tags.json`과 `hidden_tags.json`에서 읽습니다.
배포자료는 **복제**로 비배포 프리셋을 만들어 편집합니다. **새로고침** 옆의 **배포 풀기**는
경고 확인 후 배포 프리셋 수정·삭제·숨기기·복원과 **프리셋 구분**의 **배포 / 비배포** 선택을 허용합니다.
숨김 관리에서도 배포자료를 함께 표시하며, 잠긴 배포자료는 선택하거나 변경할 수 없습니다.
숨긴 배포자료는 배포 구분을 유지하고 선택 목록에서 빠집니다. 배포 풀기 후 **복원**으로 다시 사용할 수 있습니다.
구분을 바꾸고 저장하면 선택한 위치로 이동합니다. **배포 잠그기** 또는 화면을 나가면 다시 잠깁니다.
프로그램 업데이트는 배포 파일 전체를 확인·백업 없이 교체합니다. 이름을 바꾸거나 새로 추가한
배포 항목도 교체되며, 삭제한 항목도 배포 파일에 있으면 다시 생깁니다. 유지할 항목은 비배포로 저장하세요.
실행 엔진도 배포자료를 함께 읽으며,
같은 이름의 사용자 프리셋이 있으면 실행 시 사용자 값을 사용합니다.

초기 배포자료는 원본의 활성 항목만 포함합니다. 표정 664개와 구도 531개를 같은 이름끼리
합쳐 **표정·구도 670개**, **품질 12개**, **네거티브 13개**를 제공합니다.
표정·구도에서 `1girl` 522개를 제거하고, `SDstudio-80종공유용2/` 접두사를
`SD-80_`으로 변경했습니다. 나머지 이름의 `/`와 `\`도 `_`로 변경했습니다.
외모·복장·아티스트·자연어·캐릭터 네거티브와 원본 숨김 항목은 배포자료에 포함하지 않습니다.

SD studio 가져오기는 구조 분석 → 항목 선택·수동/LLM 분류·태그 편집 → 충돌 비교·저장 순서입니다.
LLM 분류는 저장된 LLM1~LLM10 설정을 사용하며 미분류 태그를 30개씩 처리합니다.
같은 이름은 기존 값 유지·다른 이름으로 추가·교체를 선택할 수 있고, 선택한 씬으로 체인 프리셋을 생성할 수 있습니다.
네이티브 JSON 내보내기·가져오기는 제공하지 않습니다.

저장은 원본 엔진의 프리셋 처리와 백업·원자적 저장 로직을 재사용합니다.
`/api/setting/presets` 및 하위 동작 API에 설정 헤더를 사용하고, 변경 요청은 `If-Match`로
검토 이후 다른 창에서 바뀐 내용을 덮어쓰지 않도록 합니다.

## 워크플로우 관리

**리소스 관리 → 워크플로우 관리**에서 최신 복호화 팩과 워크플로우 폴더의 항목을 함께 확인합니다.
동봉 V6 팩은 14개이며, 여섯 개의 탭 안에서 세부 그룹을 제공합니다. 배포 전 수정에서는 팩 버전 V6을 유지합니다.

- 삽화 2개: V4 ANIMA+ILXL, V4 ANIMA
- 에셋 2개: V4 ANIMA+ILXL, V4 ANIMA
- 편집 1개: ANIMA 인페인팅
- 학습 4개: 캐릭터·스타일 LoRA 각각 ANIMA와 ILXL
- 유틸리티 5개: 얼굴 추출, 범용 태그 분석, 얼굴 태그 분석, 삽화 유틸리티, 디버깅
- 미분류: 사용자가 폴더에 저장한 워크플로우

워크플로우 폴더(`data/comfy/user/default/workflows`)의 하위 폴더까지 UI/API 형식의 JSON 워크플로우를 읽습니다.
팩 원본과 내용이 같은 파일은 이름이 달라도 `팩 + 폴더`로 합쳐 표시합니다. 다른 내용의 사본은 별도의 사용자 워크플로우입니다.
사용자 워크플로우는 파일 내용이 바뀌어도 경로가 같으면 그룹 설정을 유지합니다. 파일을 추가하거나 제거한 뒤 **새로고침**으로 목록을 갱신합니다.
사용자 항목은 자유롭게 그룹을 이동할 수 있으며, E2E·무결성 검증은 각 팩 워크플로우 행에서 사용할 수 있습니다.

ANIMA 고속·고속 8GB 삽화 변형은 제외하고 ANIMA 기본형 하나로 정리했습니다.
파일명은 `배포_공방_{용도}_{모델}_{옵션}_V{버전}.json`으로 통일합니다.
삽화·에셋 4개는 `V4`로 표기하고, 이후 변형이 생기면 세부 버전을 붙입니다. 나머지는 기존 버전 번호를 유지합니다.
모델명 없는 공통 도구는 모델 부분을 생략합니다.
삽화 V1, ILXL 단독 에셋, Qwen Edit, 영상 워크플로우는 동봉 팩에서 제외했습니다.
이전에 설치된 팩과 사용자 파일은 보존하며, 관리 화면에는 최신 배포 팩을 표시합니다.
삽화·에셋·학습 탭은 **모델 그룹**으로 묶습니다. 삽화·에셋은 ANIMA와 ANIMA+ILXL,
학습은 ANIMA와 ILXL로 나누며, 같은 모델의 캐릭터·스타일 학습을 함께 표시합니다.
그룹 버튼은 해당 워크플로우만 표시하는 필터이며, 검색과 함께 적용됩니다.
**전체** 버튼으로 해당 탭의 그룹 필터를 해제합니다.
각 사용자 워크플로우 행의 **그룹 이동**에서 분류 탭과 모델 그룹 또는 하위 그룹을 변경합니다.
배포 워크플로우는 기본 그룹을 유지하며, 화면과 서버에서 그룹 이동을 차단합니다.
기존 그룹 이름을 사용하거나 새 이름을 입력할 수 있으며, **분류 추가**로 여러 그룹에 포함할 수 있습니다.
다른 워크플로우의 분류는 유지되며, 마지막 항목이 빠진 빈 그룹은 목록에서 사라집니다.
그룹 영역은 표시 필터만 제공합니다.
그룹 설정은 `config/workflow-groups.json`에 원자적으로 저장하며, ETag로 다른 창의 변경 덮어쓰기를 막습니다.
그룹 파일이 없으면 배포 목록에서 기본 분류를 구성합니다. 기존 실행 경로와 워크플로우 파일은 변경하지 않습니다.

각 행의 **E2E 검증**은 기존 `ComfyInstallerService.start_e2e`를 통해 해당 배포 원본 한 개를 별도 ComfyUI에서 실제 실행합니다.
진행 상태·로그·검증 결과·중단을 지원하고, 검사 방법이 없는 항목은 사유를 표시합니다.
실행 중인 관리 Comfy 인스턴스, 모델 다운로드, 설치·검증 작업이 있으면 E2E 시작을 막습니다.
각 행의 **무결성 검증**은 해당 항목의 배포 원본 SHA-256과 현재 연결된 파일을 비교하고 정상·원본과 다름·미사용·배포 원본 오류를 구분합니다.
화면을 여는 것만으로 E2E 실행이나 무결성 검증을 시작하지 않습니다.

API는 `GET /api/setting/workflows`, `GET /api/setting/workflows/status`,
`POST /api/setting/workflows/{e2e|integrity|cancel}`, `GET·PUT /api/setting/workflows/groups`입니다.
모든 요청에 `X-Comfy-Settings: 1`, `X-Comfy-Settings-Schema: 2`가 필요합니다.
검증 요청은 `releaseVersion`과 `selectedItemIds`를 받습니다.

## Comfy 실행 관리

**백엔드 관리 → Comfy 실행 관리**에서 **Comfy#1**, **Comfy#2**, **Comfy#3** 탭을 선택합니다.
각 인스턴스의 실행·종료, ComfyUI 접속, VRAM/RAM 정리, 실행 상태와 로그를 제공합니다.
포트, GPU 번호, VRAM 모드, CORS·외부 접속, Fast 모드, DynamicVRAM, 추가 실행 인자를
변경하면 자동 저장되며 다음 실행에 적용됩니다. 저장 대기·저장 중·저장 완료 상태를 표시하고, 저장 실패 시 다시 시도하거나 저장된 설정을 다시 불러올 수 있습니다. **실행**은 대기 중인 변경 사항의 저장이 완료된 뒤 시작합니다.
**매니저 시작 시 자동 실행**도 변경 시 자동 저장되며, 켜두면 설정 서버가 시작될 때 해당 인스턴스를 실행합니다.
실행·종료 요청을 처리하는 동안에는 버튼이 회색으로 비활성화됩니다. 실행 중에는 실행 버튼을, 중지 상태에서는 종료 버튼을 회색으로 표시합니다.
설정 서버를 종료하면 이 서버에서 실행한 Comfy 프로세스도 종료합니다.

원본 실행 엔진 `ComfyRuntimeManager`와 `config/settings.json`의 `appConfig.comfy_launch_profiles`,
`comfyui_port`, `comfyui_port_2`, `comfyui_port_3`을 재사용합니다. 기본 포트는 8188, 8187, 8186입니다.
다른 실행기가 사용 중인 포트에서는 중복 실행을 거부하며, 다른 실행기의 프로세스를 종료하지 않습니다.
설정 서버가 관리하는 Comfy가 실행 중이면 초기 설치를 차단합니다.
`GET /api/setting/comfy-runtime`은 세 인스턴스 상태를 반환하고,
`POST /api/setting/comfy-runtime/{1|2|3}/{config|start|stop|free-memory}`는 해당 인스턴스를 제어합니다.
설정 API와 같은 로컬 요청·스키마 헤더 검사를 사용하며, 저장·실행은 인스턴스별 `If-Match`로 오래된 요청을 거부합니다.

초기 설치는 `01 · Civitai API 키`와 `02 · 암호키`로 구성합니다.
두 값은 기타 API 관리에서도 같은 저장 항목을 편집합니다. Civitai는 바로가기와 키 입력만 제공하며,
엔드포인트 및 사용 여부를 설정하지 않습니다. 키 입력은 가리지 않고 표시합니다.

## 실행

Windows에서는 설치 폴더의 **`Comfy공방.exe`를 더블클릭**합니다.
서버가 시작되면 브라우저가 자동으로 열리고, 이미 실행 중이면 화면만 다시 엽니다.
화면 소스가 변경되었거나 빌드 결과가 없으면 실행 시 자동으로 빌드합니다.
사용 중에는 실행 창을 열어 두고, 종료할 때는 해당 창에서 `Ctrl+C`를 누릅니다.
실행 파일은 `src` 폴더와 함께 두세요. 다른 위치에서 열려면 실행 파일의 바로가기를 만드세요.
**프로그램 로그 → 프로그램 출력**의 **설정 서버**, **삽화·LoRA 실행** 출력은
현재 서버 실행 중에만 보관하며, 서버 종료 시 삭제합니다. 강제 종료로 남은 출력도 다음 시작 시 초기화합니다.

실행 파일 재빌드는 설치 폴더에서 아래 명령을 사용합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File src/packaging/windows/build_launcher.ps1
```

수동 실행:

```powershell
# src/settings_ui에서
npm ci
npm run build

npm run preview
```

주소는 **http://127.0.0.1:8201/setting**입니다. 관리 화면은 `127.0.0.1:8201`에만 바인딩하며, 외부 삽화 요청은 별도의 `8202` 포트에서 처리합니다.
`--no-browser`를 지정하면 브라우저를 자동으로 열지 않습니다.
`src/settings_ui`의 `npm run preview`도 같은 Python 설정 서버를 실행합니다.

개발 중에는 Python 설정 서버를 실행한 상태에서 별도 터미널의 `src/settings_ui`에서
`npm run dev`를 실행합니다. 이 명령은 변경된 프론트엔드를 자동으로 다시 빌드합니다.
빌드 후 브라우저를 새로고침하면 반영되며, 추가 웹 서버 포트를 사용하지 않습니다.
배포에는 빌드된 `settings_ui/dist`를 포함해야 합니다.

## 설정 저장

LLM API 관리는 **프로바이더 공통 설정**, **LLM 설정**, **외부 LLM 분기** 탭으로 구성합니다.
**프로바이더 추가**에서 먼저 LLM 서비스를 선택하고 이름, 베이스 URL, API 키(Vertex는 서비스 계정 JSON),
동시 요청 수를 입력합니다. 이름을 비우면 서비스 이름을 사용합니다.
서비스 선택지는 원본과 같은 Vertex Gemini, Gemini AI Studio, OpenAI 호환 URL, Claude 네 개입니다.
Ollama 같은 호환 서비스는 OpenAI 호환 URL을 선택하고 프로바이더의 베이스 URL에 주소를 입력합니다.
**LLM 설정**에서는 LLM1~LLM10을 선택한 뒤 사용할 프로바이더, 모델명, 별칭,
스트리밍, 추론, 토큰, Custom Body/Headers를 한 폼에서 편집합니다.
각 LLM의 **테스트** 버튼을 누르면 저장된 프로바이더와 모델, 생성 옵션으로 메시지를 전송할 수 있습니다.
PNG·JPEG·WebP 이미지는 최대 6장, 합계 8MB까지 첨부할 수 있습니다.
응답 내용, 경과 시간, 제공되는 토큰 수를 표시하며, 스트리밍을 켠 LLM은 응답을 실시간으로 보여줍니다.
**중지**하거나 테스트 창을 닫으면 진행 중인 요청을 취소합니다.
같은 프로바이더를 선택한 LLM들은 서비스 종류, 베이스 URL, 인증 정보, 동시 요청 상한을 공유합니다.
프로바이더의 **삭제** 버튼은 해당 설정과 키를 삭제하고, 이 설정을 사용하던 LLM의 프로바이더 선택을 해제합니다.
모델명과 생성 옵션은 유지됩니다. 마지막 프로바이더도 삭제할 수 있으며, 프로바이더를 다시 선택하기 전에는 API를 호출하지 않습니다.
숫자 입력은 유효한 값을 입력하고 입력칸을 벗어나면 저장됩니다.

**외부 LLM 분기**는 편집 가능한 작업을 9개 분류로 표시합니다.
**01 LoRA 관리**에는 봇·에셋·스타일 LoRA 정제와 테스트 이미지 일괄 세팅을 모읍니다.
**02 프리셋 관리**에는 **프리셋 가져오기 분류**를 표시합니다.
**03 에셋 관리**에는 에셋 이름 자동 수정·전체 매핑을, **04 에셋 편집**에는 **EDIT 지시 영어 번역**을 표시합니다.
**05 에셋-캐릭터 메이커**에는 캐릭터 초안 작성과 생성 이미지 피드백을 모읍니다.
**06 삽화 봇 만들기**에는 얼굴/눈 태그 분류, 외모/복장 태그 정제, 프로필 선택 기준 자동 작성과 대표 이미지 외형 분석을 모읍니다.
**07 삽화 생성 파이프라인**에는 수동 그리기와 등장인물·프로필·에셋 선택, OUTFIT, TIME & PLACE, PLAN, KEYVIS, DETAIL,
대사를 만드는 POST PROCESS, 다중 캐릭터 마스크 생성, 삽화 비주얼 교정과 삽화 비주얼 교정 결과 선택을 모읍니다.
각 항목은 한글 기능명 뒤 괄호에 실제 처리 흐름의 노드 이름을 표시합니다. 삽화·만화가 설정을 공유하면 두 노드 이름을 함께 표시하며,
별도 처리 흐름 노드가 없는 **수동 그리기**는 기능명만 표시합니다.
**08 삽화 수정**에는 삽화 편하게 수정, 이미지 분석과 삽화 오토피드백 검수를 모읍니다.
**09 개발자 옵션 및 비사용 옵션**에는 삽화 품질 자동 검사, LoRA 프롬프트 2차 검수·오토피드백과 MiniMax H3 영상화의 7개 작업을 모읍니다.
MiniMax H3 영상화의 별도 그룹은 제거하고 해당 작업들의 메인·폴백 및 재시도 설정은 유지합니다.
원본에서 잠긴 3개 작업은 설정값을 보존하고 화면과 일괄 적용에서 제외하며, 표시할 작업이 없는 그룹은 숨깁니다.
**쉬운 설정**에서 텍스트·비전 요구 작업별 메인/폴백 LLM, 대기(초), 추가 횟수를 일괄 적용하고,
**상세 설정**에서 작업별로 편집합니다. LLM 선택에는 LLM1~LLM10의 별칭 또는 모델명을 표시합니다.
분기 설정은 `draft.llmRouting`에 자동 저장하며, 초기 로드 때 기존 `config.json`의 `llm_routing`을 가져옵니다.
작업 목록과 기본값은 `llm_routing_catalog.json`을 프런트엔드와 설정 서버가 공유합니다.
저장한 라우팅은 `runtime_config()`를 통해 실제 작업 호출에 적용됩니다.

기존 슬롯 설정은 첫 로드 때 가져오며 서로 다른 키나 베이스 URL은 별도 프로바이더로 보존합니다.
V6의 기존 `config.json`은 필요한 값을 `settings.json`의 `appConfig`로 옮긴 뒤 백업하고 제거합니다. 실행 엔진은 저장된 공통 설정을 읽어
텍스트·비전·스트림의 기존 요청 제한에 적용합니다.

- `app_paths.config_root()`로 찾은 프로젝트의 **`config/settings.json`**을 사용합니다.
- 설치 계획, 업데이트 정책, 모델·LoRA의 표시 정보와 선택, LLM·기타 API 구성과 키를 저장합니다.
- Comfy 연결·실행 옵션과 작업 설정은 같은 파일의 `appConfig`에 저장합니다. UI와 실행 엔진의 쓰기는 프로세스 간 잠금과 원자적 교체를 사용하며 다른 영역을 보존합니다.
- LLM 병렬 제한은 프로바이더 설정을 기준으로 큐와 요청 제한기가 함께 적용합니다. 카드 일괄 정제는 여러 요청을 준비하고 실제 API 동시 호출 수는 서버가 제한합니다.
- Civitai 키는 `apiKeys.other-civitai`, 복호화용 암호키는 `apiKeys.workflow-key`를 사용합니다.
- 사이드바 접힘 상태는 현재 창에서만 유지합니다.
- 설정을 읽은 후 편집을 허용하며, 변경 사항은 400ms 후 자동 저장합니다.
- 연속 변경은 순서대로 기록합니다. `저장됨`은 서버의 파일 쓰기가 성공한 뒤 표시합니다.
- 파일을 임시 파일에 쓰고 교체하여 중간 실패로 기존 파일이 잘리지 않게 합니다.
- 여러 창에서 동시에 변경하면 ETag로 충돌을 감지하고 오래된 설정의 덮어쓰기를 막습니다.
- 읽기·저장 오류는 화면에 표시하며, 오류가 있는 파일을 기본값으로 덮어쓰지 않습니다.
- 기존 localStorage 설정은 서버 파일이 없을 때 한 번 가져옵니다. 서버 저장이 확인된 뒤
  기존 브라우저 항목을 제거합니다. 새 값은 localStorage에 쓰지 않습니다.

API 키도 설정 파일에 저장되므로 새로고침 후 유지됩니다. `config/*`는 Git에서 제외하며 빈 `.gitkeep`만 예외입니다.
이 파일은 정적 웹 경로로 제공하지 않습니다. 설정 API 응답은 `Cache-Control: no-store`를 사용하며,
서버는 요청 본문이나 키를 로그에 기록하지 않습니다.

## 서버 요청

`GET /api/setting/config`로 문서와 ETag를 받고, 같은 ETag를 `If-Match`에 넣어
`PUT /api/setting/config`로 저장합니다. 두 요청 모두 `X-Comfy-Settings: 1`과 `X-Comfy-Settings-Schema: 2` 헤더가 필요합니다.
PUT은 `application/json`만 받습니다. 설정 형식은 `settings_store.py`에서 검증합니다.

외부 삽화 요청의 진입점은 `0.0.0.0:8202`입니다. RisuAI의 Comfy 요청·결과 조회·WebSocket과
Soya Comfy 브리지 요청만 명시적으로 허용하고, 같은 공방의 삽화 작업 서버에서 처리한 응답을 반환합니다.
`8202`에는 관리 화면·설정·API 키·주소 발급 API가 없습니다. `8201`은 Host·Origin·Sec-Fetch-Site를
검사하며 외부 Origin의 요청과 CORS를 허용하지 않습니다. 외부 요청의 내부 인증 헤더나 쿠키는 전달하지 않습니다.

삽화 사이드바의 **삽화 → 외부 연결 → 작업 내역 관리** 순서에서 **랜덤 주소**와 **고정 주소**를 사용합니다.
랜덤 주소는 Cloudflare Quick Tunnel의 주소 발급·복사·재발급·연결 종료를,
고정 주소는 Tailscale Serve의 주소 발급·복사·연결 종료를 제공합니다.
두 방식 모두 `http://127.0.0.1:8202`로 연결하며, Tailscale HTTPS 포트도 `8202`입니다.
한 번에 한 방식만 발급하고, 각 탭에 연결됨·미연결·확인 불가 상태를 주기적으로 갱신합니다.
기존 공유 및 연결 가이드의 링크·Workflow JSON·설명 이미지를 그대로 제공하며 발급 주소를 가이드에도 반영합니다.
프로그램 종료 시 공방의 연결만 정리하고 다른 포트의 Tailscale 설정은 유지합니다.

공용 경로는 `app_paths.py`, 원자적 JSON 쓰기는 `json_store.py`를 재사용합니다.

## 초기 설치

`03 · 기본설치`와 `호환 설치`는 기존 `ComfyInstallerService`를 호출합니다. 호환 설치는 기존 NVIDIA
호환 프로필을 사용하며 SageAttention과 전용 Triton을 제외합니다. 버튼을 누르면 아래에 CMD 형태의
설치 콘솔이 펼쳐지고, 실제 설치 로그와 진행 상태를 1초마다 갱신합니다. 로그는 최신 줄을 따라가며,
위로 스크롤해 읽는 동안에는 위치를 유지합니다. 콘솔 접기·펼치기와 설치 중단을 지원합니다.
설치 버튼 옆에는 Civitai API 키·암호키 미입력, 설정 저장 대기·오류, 서버 연결 및 설치 진행 상태 등
설치를 시작할 수 없는 사유를 함께 표시합니다. 입력과 상태 변화에 따라 즉시 갱신하며,
두 키가 입력되고 저장 및 상태 확인이 끝나면 `설치 가능`으로 바뀌고 두 설치 버튼이 활성화됩니다.
내장 ComfyUI 폴더를 사용하는 프로그램이 있으면 PID·포트를 표시하고 설치 버튼을 비활성화합니다.
Comfy 실행 관리에서 시작한 인스턴스 외에 별도 실행한 ComfyUI와 내장 Python을 사용하는 도구도
확인하며, 설치 요청 시점과 기존 폴더 삭제 직전에도 다시 검사합니다. 프로그램을 종료하면 안내가 자동으로 갱신됩니다.

저장된 암호키로 동봉한 `comfy_installer/resources/workflows.soyawfp`를 복호화한 뒤,
공용 분석·얼굴 추출·유틸 작업 바인딩에 해당하는 5개를 설치합니다.
디버깅, 로라 얼굴 추출기, 범용 태그 분석, 삽화 유틸, 얼굴 태그 분석이 대상입니다.
기본 파일명은 `배포_공방_`으로 시작하고 `_v1.json`으로 끝납니다.
모델 다운로드 대상은 선택한 워크플로우의 팩 명세로 결정합니다.
Anima 2.9B와 기존 Anima용 텍스트 인코더·VAE, 기본 제공 LoRA는 워크플로우 선택과 관계없이
초기 설치에 포함합니다. 같은 모델이 워크플로우에서도 필요하면 한 번만 설치합니다.

관리 워크플로우는 `data/comfy/user/default/workflows` 바로 아래에 원래 파일명으로 저장합니다.
`SOYA_USER` 하위 폴더와 자동 `__vN` 접미사는 만들지 않습니다. 갱신은 읽기 전용 해제 → 삭제 →
새 파일 저장 → 읽기 전용 부여 순서이며, 이 파일들의 백업은 만들지 않습니다.
실패는 설치 오류로 보고하고 다시 설치할 때 배포 원본으로 재시도합니다. 다른 파일은 변경하지 않습니다.

`POST /api/setting/install`은 `install_mode` (`standard` 또는 `nvidia_compatibility`)와 저장된 설정의
`If-Match`를 받습니다. 키는 서버가 `config/settings.json`에서 읽습니다. Civitai 키는 기존 설치 엔진의
키 저장 함수를 통해 반영하고 설치 결과의 실행 설정은 같은 `config/settings.json`의 `appConfig`에 저장합니다.
`GET /api/setting/install`로 진행 상태를, `POST /api/setting/install/cancel`로 중단을 요청합니다.
세 요청 모두 `X-Comfy-Settings: 1`이 필요합니다.

화면은 shadcn/ui의 Sidebar·Field 패턴을 참고하며, Lucide 아이콘과 번들에 포함된 Noto Sans KR을 사용합니다.

## 모델·LoRA 라이브러리

ComfyUI LoRA Manager의 세로 썸네일 카드 구성을 참고합니다. 두 페이지는 공용 React 카드로
썸네일, 이름, 기반 모델, 트리거를 표시합니다. 목록은 프로젝트 내부의 `data/comfy/models`를 읽으며,
`loras` 하위 파일은 외부 LoRA 관리에, 나머지 모델 파일은 모델 관리에 표시합니다. 외부 경로 설정이나
프로젝트 밖으로 연결된 심볼릭 링크·정션은 읽지 않습니다. 새로고침으로 파일 추가·삭제를 반영합니다.
모델 카드 오른쪽 위 `+`는 카드를 선택하며, 선택된 카드의 체크 버튼을 누르면 선택을 해제합니다.
설치 출처를 확인할 수 있는 항목은 썸네일·이름·편집 버튼으로 여는 `모델 편집` / `LoRA 편집` 창에
`모델 페이지`를 표시하며 Civitai 모델·버전 페이지 또는 Hugging Face 저장소를 새 탭에서 엽니다.
페이지 주소는 설치 명세와 모델 옆 메타데이터에서 구하며, 설치용 파일 다운로드 주소와 구분하고 인증 키는 포함하지 않습니다.
기존 설치 항목도 목록을 읽을 때 페이지 주소를 구하므로 재설치할 필요가 없습니다.
모델 페이지를 확인할 수 없는 항목은 링크를 표시하지 않으며, Civitai 버전 정보가 있으면 `Civitai 정보 새로고침`으로 보완할 수 있습니다.
편집 창의 `예시 이미지`에서 저장된 예시 이미지·영상을 넘겨 보고, 이미지별 프롬프트·네거티브 프롬프트를
복사할 수 있습니다. Steps·Sampler·CFG·Seed 등 생성 설정과 중첩된 생성 정보도 함께 표시합니다.
`모델 정보`는 제작자·태그·버전 설명·모델 설명·제작자 트리거·통계를 보여주며,
`전체 메타데이터`에서 저장된 정보를 복사하거나 `JSON 다운로드`로 받을 수 있습니다.
외부 설명은 텍스트로 표시하고, 인증 정보는 메타데이터 응답에서 제외합니다.
예시 미디어는 출처 URL에서 불러오며, 출처에서 공개하지 않은 프롬프트는 만들어 채우지 않습니다.
`Civitai 정보 새로고침`은 모델 파일을 다시 받지 않고 예시·프롬프트·설명·제작자 정보를 갱신합니다.
새 Civitai 다운로드도 버전 정보와 모델 설명·제작자 정보를 함께 저장합니다.
초기 설치와 `모델 설치`·`LoRA 설치`는 기존 메타데이터 파일이 있어도 출처 정보를 수집해 보완합니다.
기존 노트·즐겨찾기 등 사용자 정보는 유지하고, 비어 있는 설명·트리거·태그와 LoRA Manager 호환 필드를 채웁니다.
파일이 없으면 `아직 설치 전입니다`를 표시합니다. 모델 로딩 설정은 제공하지 않습니다.

기반 모델·트리거는 모델 옆의 `.metadata.json`, `.civitai.info`, `.json`을 함께 읽어 보완합니다.
모델 확장자가 붙은 메타데이터 파일명과 중첩된 Civitai 정보도 지원하며, 정보가 부족하면
safetensors 내부 메타데이터에서 기반 모델과 명시된 트리거·학습 클래스 토큰을 읽습니다.
학습 태그 빈도 전체를 트리거로 취급하지 않습니다. 썸네일은 모델 옆의 이미지를 사용합니다.
이름·트리거는 파일에서 읽은 원본 정보를 읽기 전용으로 표시합니다. 편집 창의 `별칭 (선택)`에
프로그램 안에서 표시할 이름을 지정할 수 있으며, 비워두면 원래 이름을 사용합니다.
기존에 편집한 이름은 별칭으로 이어서 사용하고, 기존 트리거 편집값 대신 파일의 트리거를 표시합니다.
외부 LoRA 편집에는 `커스텀 트리거 (선택)`을 별도로 저장할 수 있습니다. 비워두면 미지정이며,
원본 트리거는 유지합니다. 입력한 커스텀 트리거는 카드에서 확인·복사하거나 검색할 수 있습니다.
입력란 옆 `?` 도움말은 마우스 호버·키보드 포커스로 표시하며 Escape로 닫을 수 있습니다.
별칭·기반 모델 등 편집한 표시 정보와 선택은 `config/settings.json`에 저장하며,
저장된 항목만으로 카드를 만들지 않습니다. 기존의 예시 목록도 표시하지 않습니다.
검색은 원래 이름·별칭·기반 모델·트리거를 포함합니다. 이름 정렬은 표시되는 이름을 기준으로 합니다.
캐릭터·Face·그림체 및 공통 LoRA의 `LoRA 추가` 창은 `외부 LoRA`와 `내부 LoRA` 탭으로 구분합니다.
내부 탭에서는 에셋·봇·그림체 학습 결과를 프로젝트·캐릭터·세션 이름과 트리거로 검색합니다.
학습 목록의 이름·트리거·대표 이미지를 연결하고, 실제 모델 폴더에서 찾은 내부 파일도 함께 표시합니다.
선택하면 기반 모델·강도·트리거를 채우며, 같은 파일은 중복 추가할 수 없습니다.
새로고침은 현재 검색 위치의 목록을 갱신하며, 일부 내부 목록의 조회가 실패해도 확인된 결과는 선택할 수 있습니다.
모델 관리에는 기반 모델 선택 필터를 두지 않으며, 이름·용량을 각각 오름차순·내림차순으로 정렬합니다.
용량은 실제 바이트 수를 비교하며, 용량이 같으면 이름 오름차순으로 표시합니다.
트리거 버튼과 복사 아이콘으로 클립보드에 복사할 수 있습니다.
모델 목록 탭은 `전체`와 `Checkpoint`, `Upscaler` 등 모델 폴더에서 정해지는 유형별 개수를 표시합니다.
외부 LoRA 관리는 `전체`와 설치된 LoRA의 기반 모델별 탭·개수를 표시합니다. 학습으로 만든 내부 LoRA가 있는
`loras/SOYA_CHAR_LORA` 폴더는 스캔하지 않으므로 내부 LoRA는 이 목록에 표시되지 않습니다. 기반 모델 정보가 없으면
`미확인` 탭으로 모읍니다. LoRA의 분류는 `모든 분류` 필터에서 선택하며 편집 창의 `분류` 값을 사용합니다.
탭은 검색·정렬과 함께 적용되고 LoRA에서는 분류 필터도 적용되며, 방향키·Home·End로도 이동할 수 있습니다.
삭제·정보 편집·새로고침으로 현재 탭에 해당하는 항목이 없어지면 `전체`로 돌아갑니다.
설치 명세에 등록된 모델·LoRA는 `필수 모델`로 표시하고 삭제 버튼을 비활성화합니다. 서버도 삭제 직전에
현재 명세의 설치 경로를 다시 확인하며, 명세를 읽을 수 없으면 삭제를 허용하지 않습니다.
별칭·분류 등 표시 정보를 편집해도 삭제 보호는 유지됩니다.

모델/LoRA 편집 창의 현재 위치 아래 `폴더 이동` 버튼이나 카드의 폴더 아이콘에서 대상 폴더와
하위 폴더를 선택할 수 있습니다. 편집 창에서는 입력한 표시 정보를 적용한 뒤 이동 창을 엽니다. 체크포인트에 잘못 저장된
Anima 모델은 `Diffusion · diffusion_models`로 이동하세요. Anima 기반 모델로 확인된 체크포인트는
이동 창에서 Diffusion을 기본 선택합니다. 외부 LoRA는 `loras` 안에서 하위 폴더를 변경할 수 있습니다.
썸네일과 메타데이터도 함께 이동하며, 다른 형식의 모델과 공유하는 파일은 복사하여 원본을 유지합니다.
별칭·기반 모델·선택 상태는 새 경로로 이어지고, 이동한 모델의 분류와 목록을 즉시 갱신합니다.
같은 이름의 모델·미리보기·메타데이터는 덮어쓰지 않으며, 필수 모델의 원래 위치와 설치 대상 위치는
이동으로 변경할 수 없습니다. 초기 설치나 모델 다운로드 중에는 완료 또는 일시 정지 후 이동합니다.
워크플로우 파일은 자동 수정하지 않으므로, 하위 폴더를 바꾸면 워크플로우의 모델 경로를 다시 선택하세요.

각 설치 버튼 바로 옆의 `모델 업로드`와 `LoRA 업로드`에서 컴퓨터의 파일을 직접 등록할 수 있습니다.
모델은 저장 폴더를 선택하고, LoRA는 `loras`에 저장합니다. 하위 폴더, 기반 모델, 트리거와
미리보기 이미지(PNG·JPEG·WebP, 최대 10 MB)는 선택 사항입니다. 파일은 나누어 전송하며
업로드 진행률을 표시하고, 저장이 완료되면 목록을 자동으로 새로고침합니다.
같은 이름의 기존 파일·미리보기·메타데이터는 덮어쓰지 않습니다. 업로드에도 초기 설치 완료가
필요하며, 초기 설치나 모델 다운로드가 진행 중이면 완료 또는 일시 정지 후 업로드합니다.

`모델 설치`와 `LoRA 설치`에서 Civitai, Hugging Face, CivArchive 주소를 입력할 수 있습니다.
여러 주소는 한 줄에 하나씩 입력하며, 파일 정보를 불러온 뒤 버전·파일·설치 폴더를 선택합니다.
`파일 정보 불러오기`와 `선택한 파일 설치` 옆에 주소 미입력, 파일 정보 조회 필요, 파일 미선택,
요청 처리 중, 다운로드 진행 중, 상태 조회 실패 등 비활성화 사유를 빨간색으로 표시합니다.
설치 창이 열려 있는 동안에도 다운로드 목록과 파일별 실패 사유를 창 안에 표시하며,
다운로드 상태는 1초마다 갱신하고 연결 오류가 해소되면 안내와 버튼 상태도 갱신합니다.
Hugging Face는 저장소, 하위 폴더, `blob`·`resolve` 파일 주소를 지원합니다.
다운로드는 프로젝트 내부 `data/comfy/models`에만 저장하고, 완료한 파일은 목록에 자동 반영합니다.
Civitai와 Hugging Face의 인증은 기타 API 관리에 저장된 키를 사용합니다.
모델·LoRA 설치와 이어받기는 ComfyUI 소스, 전용 Python 환경, 초기 설치 완료 기록이 있어야
허용합니다. ComfyUI 미설치 사유는 목록과 설치 창에 빨간색으로 표시하며, 서버도 같은 조건을 검사합니다.
Civitai 주소와 버전 ID는 Civitai API 키가 입력·저장되어야 조회·설치·이어받기를 할 수 있습니다.
Hugging Face 공개 파일에는 Civitai 키를 요구하지 않습니다.
설치 시 Civitai·CivArchive가 제공하는 미리보기 이미지와 Hugging Face의 모델 옆 이미지 또는
`preview`·`thumbnail`·`cover` 등의 이미지를 자동으로 저장해 라이브러리 썸네일에 사용합니다.
Hugging Face는 모델과 같은 이름 또는 `모델명.preview` 이미지를 우선하고, 다음으로
`preview`·`thumbnail`·`cover`·`example`·`sample` 이름, `preview_00001`·`sample-1`처럼
해당 이름 뒤에 구분자(`_`, `-`, `.`, 공백)와 설명·번호가 붙은 이미지를 찾습니다.
우선순위와 경로 이름순으로 정렬한 최대 3개 후보를 시도하며, PNG·JPEG·WebP와 10 MiB 이하만 허용합니다.
메타데이터는 Civitai·CivArchive의 버전 응답과 Hugging Face의 해당 모델 옆 JSON 파일을 저장하고
트리거·기반 모델을 해석합니다. 초기 설치와 워크플로우의 필수 모델 설치에도 같은 처리를 적용합니다.
메타데이터 취득에 실패해도 모델 다운로드 완료 상태를 유지하고 안내를 표시합니다.
기존 이미지는 유지하며, 원본에 이미지가 없으면 썸네일 없이 표시합니다. 이미지 취득에 실패하면
모델 파일의 다운로드 완료 상태를 유지하고 별도 안내를 표시합니다. 완료 표시는 `다운로드 완료`로 구분합니다.
다운로드 목록에서 진행률·속도를 확인하고 일시 정지·이어받기·중단·실패한 항목 재시도를 할 수 있습니다.
부분 파일은 `.part`로 보관해 이어받으며, 기존의 다른 모델 파일은 덮어쓰지 않습니다.
폴더 조회나 설정 화면 열기만으로 외부 파일을 검색하거나 다운로드하지 않습니다.

내장 ComfyUI의 LoRA Manager는 `custom_nodes/comfyui-lora-manager/settings.json`의
휴대용 설정을 사용합니다. 설치·업데이트·실행 시 모델 경로를 이 설치의 `data/comfy/models`에
맞추고 설정·캐시를 다른 ComfyUI 설치와 분리합니다. Civitai 키 교체도 이 전용 설정에 적용합니다.

## 암호화 배포 요구사항

GitHub 배포본에는 워크플로우와 프리셋을 암호화한 상태로 포함합니다. 설치 과정에서 사용자가 입력한
암호키로 복호화하며, 복호화에 성공해야 해당 리소스를 사용합니다. 배포 암호는 공개 소스·기본값·도움말에
기록하지 않습니다. 기존 팩 암호화·복호화 구현은 `comfy_installer/crypto.py`에 있습니다.
