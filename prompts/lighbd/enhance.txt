PURPOSE

Fill the supplied character-by-time table sparsely with outfit and hairstyle image tags. The server expands your checkpoints to the right; you do not output the table or repeat unchanged tags at every SLOT. Characters are already resolved. Do not select scenes or change identities.

CONTEXT AND CHRONOLOGY

Use the fixed canonical roster exactly. Read the full source semantically, including who owns or wears each garment and the chronology of dressing, removal, replacement and hair arrangement. PAST HISTORY and saved state memory establish the state before CURRENT; later narrative facts supersede older memory. Preserve established garment identity, color and material when a later mention is shorter. Selected Profile/lb.extra fills only aspects neither narrative nor memory establishes; a saved state does not suppress useful fixed hair details from the selected Profile. An unclothed narrative state must not acquire default garments.

The empty table's columns are actual server SLOT boundaries in chronological order, not Cxxx segment numbers. The slotted CURRENT and segment-to-slot alignment locate each column in the story. A [Slot N] follows its passage: record the resulting persistent outfit/hair state at that boundary, after changes established in that passage. Establish the complete state for every canonical character in the first supplied SLOT, including that passage's changes; then emit only later changed aspects at their own SLOT. Track each person independently, even when absent from a later image. Never move a later change into an earlier column. If several changes occur before one boundary, record the final coherent state there.

SPARSE TAG CHECKPOINTS

Each person has only `outfit` and `hair`, each a comma-separated English image-tag string. `outfit` describes the complete current wardrobe, accessories and persistent garment arrangement/coverage; `hair` describes the complete current hair appearance and arrangement. Hair accessories belong to outfit. Do not include face, expression, pose, camera, background, person-count tags or transient actions. Determine the coherent state first, then express it as compact established image tags using the established Danbooru vocabulary.

Both fields are required for every person at the first SLOT. Afterward omit unchanged fields, people and entire SLOTs. When a field changes, supply its complete resulting tags, not a delta, action instruction or only the added item. The server replaces that field and copies it rightward until its next explicit checkpoint; outfit and hair propagate independently. Keep all still-worn items when a coat is removed, and remove the coat's worn tags; opening a coat leaves it worn. A removed garment is no longer worn even when held. Retain source-established exposure using suitable state tags; do not add garments or concealment. An explicitly empty string clears a field, whereas an omitted field inherits; never use an empty field to mean unchanged or unknown. A windblown braid remains braided; untying it produces a complete loose-hair state. Mere mention, pose or ordinary prop contact creates no checkpoint.

OUTPUT

Return one JSON object keyed by the supplied SLOT labels, then exact canonical names, then only the applicable `outfit`/`hair` tag strings. Example (only if these SLOTs/names are supplied):
{"SLOT0":{"canonical name":{"outfit":"blue coat, white shirt, black pants","hair":"long hair, brown hair, braid"}},"SLOT2":{"canonical name":{"outfit":"white shirt, black pants"}},"SLOT4":{"canonical name":{"hair":"long hair, brown hair, hair down"}}}

Use the actual first supplied SLOT even when its number is not zero. Output initial tags and changed checkpoints only, in column order. No table, status/event prose, commentary or extra fields.
