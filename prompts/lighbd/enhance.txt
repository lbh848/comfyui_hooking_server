PURPOSE

Resolve one coherent natural-language wardrobe state immediately before C001, then report only wardrobe and hairstyle changes established inside CURRENT.

INPUT DATA

Resolved CURRENT canonical character names:
{character_names}

Previously tracked character state:
{character_state}

Known character appearance and default outfit:
{lb_extra_costume}

Read PAST HISTORY and every numbered CURRENT segment semantically. Resolve aliases and pronouns from the discourse. Separate an object's owner, wearer, and actor: touching another person's garment does not make the actor its wearer. Do not use keyword matching or emit a separate coreference analysis.

OUTPUT

Return one JSON object with all three arrays. Keep an event array empty when no event applies.

{
  "wardrobe_at_start": [
    {
      "character": "canonical name",
      "state": "concise coherent natural-language physical wardrobe and coverage state immediately before C001"
    }
  ],
  "wardrobe_events": [
    {
      "segment_id": "C001",
      "character": "canonical name",
      "operation": "wear|add|remove|replace|open|close|adjust|nude|topless|bottomless|reset_default",
      "wardrobe_change": "short literal natural-language transition established by CURRENT",
      "state_after": "clothed|partial|nude|topless|bottomless|underwear_only|unknown",
      "evidence": "exact short excerpt from the supporting CURRENT segment or consecutive segments"
    }
  ],
  "hairstyle_events": [
    {
      "segment_id": "C001",
      "character": "canonical name",
      "operation": "replace|add|remove|reset_default",
      "hairstyle_change": "short literal natural-language arrangement transition",
      "evidence": "exact short excerpt from the supporting CURRENT segment or consecutive segments"
    }
  ]
}

HARD REQUIREMENTS

1. Copy supplied canonical names exactly. Emit one `wardrobe_at_start` entry for every supplied character. Resolve it from tracked state plus chronological PAST HISTORY; the latest established physical state wins over an earlier/default state. Never carry a CURRENT change backward into the start state. Use a supplied default only as an explicitly labeled fallback when story history does not establish the state.

2. Each start `state` must describe one physically possible instant. State every story-relevant garment that remains worn, attached, draped, lowered, pooled, carried, or nearby together with the resulting exposure. For every changed garment, make one final semantic choice about its relation to the body: it either remains worn or attached, including open, unhooked, lowered, displaced, draped, or pooled states, or it has been removed from the body. A removed garment may separately be carried or nearby. Use `fully unclothed`, `wearing nothing`, or equivalent terminal wording only when no garment remains worn or attached. If fabric remains worn or attached, describe the exact exposure without terminal wording. If a garment was removed, state that removal and do not also describe it as worn, open, unhooked, lowered, or attached. A coarse value such as `nude`, `topless`, or `bottomless` summarizes coverage only; it never erases an explicitly remaining displaced garment from the natural-language state.

3. `wardrobe_events` is a sparse change history, not a sequence of complete outfit snapshots. Emit an event only when CURRENT establishes a real before-to-after wardrobe change relative to the start state and earlier CURRENT events. A first appearance or repeated description of an existing/default outfit is not a change. Attribute the event only to the character whose worn state changes. Preserve a change that spans consecutive segments as one event using the earliest relevant segment and exact ordered evidence.

4. `wardrobe_at_start[].state` and `wardrobe_change` are the meaning-bearing handoff. `operation` and `state_after` are coarse compatibility hints and must never simplify or contradict the natural language. Use `wear`/`add` for an incremental addition, `remove` for specified removed items, `replace` for a complete transition to another outfit, `open`/`close`/`adjust` when the same garment stays worn, and `reset_default` only for a story-established return to the known default. Do not emit `set` or `contextual_reset`. Judge coverage from the physical result: lowered or displaced clothing may stop covering a region while remaining attached, and that remaining garment must stay in the natural-language transition.

5. Preserve only story-established garment, accessory, coverage, exposure, displacement, and removal facts. Do not invent or normalize colors, materials, layers, garment types, or image tags. Do not generate Danbooru tags or per-segment full outfit snapshots. A garment outside a camera view is not removed.

6. `hairstyle_events` contains only an actual before-to-after hair-arrangement change such as tying, untying, replacing, adding, removing, or restoring an arrangement. Hair color, length, texture, movement, messiness, bangs, body traits, and wearable hair accessories are not hairstyle events. A disheveled ponytail is still a ponytail unless the narrative establishes that it was undone. Preserve literal evidence and do not convert it to tag syntax.

FINAL CHECK

- One coherent start state per supplied character; every changed garment has one remaining-or-removed interpretation, with no mutually exclusive terminal and intermediate clothing claims.
- Only evidence-bearing CURRENT transitions; natural language retains meaning that coarse enums cannot express.
- Valid JSON only, with no Markdown, analysis, image tags, or extra prose.
