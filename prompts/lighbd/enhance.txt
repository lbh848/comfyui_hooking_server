PURPOSE

Track ONLY cumulative outfit and hairstyle arrangement for the fixed CURRENT canonical characters. Return one status immediately before the first CURRENT Cxxx segment for each person, followed by only the state transitions established within CURRENT. Do not choose or describe scenes or generate image tags.

INPUT AUTHORITY

The canonical roster was fixed by CHARACTER RESOLVE; copy its names exactly and do not infer a different identity. The supplied previous saved tracked-state record is an ordered chain of unmodified statuses, not just its last sentence: later statuses may change only one aspect and leave the rest unchanged. Read the entire chain to establish the state immediately before CURRENT. If it is absent for a character, use that character's selected resolved profile and lb.extra baseline as the explicitly identified fallback. Past history is background for understanding chronology and references, not permission to overwrite saved statuses with a later image descriptor. CURRENT segments are the only sources for new events. Interpret semantic changes in sequence, including who owns/wears an object and whether a hairstyle arrangement actually changes; never use keyword lists. A hair accessory worn or removed is part of wardrobe; hairstyle arrangement (braid/tie/loose, etc.) is hair state. Description of an already-established state does not itself create an event.

STATUS

Write a concise, ordinary-language `state_at_start` describing the coherent outfit AND hairstyle immediately before CURRENT, using the whole previous status chain when available. An event's `status` may describe the changed aspect with the rest of the previous state explicitly unchanged; do not discard earlier unchanged clothing or hair merely because the last event omits it. Describe resulting arrangement rather than just the gesture ("opened the jacket" by itself is insufficient: describe how it now sits). One event may update both outfit and hair. If a segment contains several separate changes to the same person, preserve their original order, even if the segment_id repeats. Preserve source-established exposure and coverage without inventing garments or concealing them. Only resulting persistent clothing or hairstyle changes become events; a transient pose, physical contact, or merely holding an ordinary prop does not. When a garment is removed from the body and carried or placed, that persistent wardrobe change and the garment's new state do matter to continuity; do not discard it as a mere held item. Do not translate statuses into Danbooru tags, change the resolved profile, create `worn`/`removed`/`body_state`, emit wardrobe_events or hairstyle_events, or make camera/composition/scene decisions.

OUTPUT

Return exactly one JSON object with these two arrays, even if there are no events:
{"state_at_start":[{"character":"canonical name","status":"coherent outfit and hairstyle immediately before CURRENT"}],"events":[{"segment_id":"C001","character":"canonical name","status":"result of this transition; unchanged aspects can remain as before"}]}.

One state_at_start entry per CURRENT canonical character, no others. Events use existing CURRENT Cxxx IDs in chronological order and only CURRENT canonical characters; no events if nothing changes. No commentary or extra fields.
