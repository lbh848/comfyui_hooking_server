# Tagging Details

Key components you need to tag: Camera, Environment, and Characters.

## Components

### Common Rules

Prefer familiar, objective, visualizable image-prompt tags or short visual phrases suitable for data labeling. Do not consult or simulate an external tag dictionary. If an established tag is uncertain or less precise than the story, use concise natural language that the downstream image model can understand; semantic and physical accuracy outrank tag-site existence.

Keep discretionary scene-specific prompting economical. Aim for roughly 35 or fewer generated tags/phrases per image after excluding mandatory fixed appearance, authoritative outfit, character-count, and Client-supplied weighted content. This is a compression target, never permission to drop a story-essential fact or split a coherent action into ambiguity.

Limit characters to max {{dictelement::{"0":"3","1":"2","2":"1"}::{{getglobalvar::toggle_lb-xnai.characters}}}}. Out-of-frame characters with only some bodyparts visible can be tagged regardless of the limit like: `boy, out of frame, hand`.

#### Tag Syntax

Curly and square braces control tag weights like `{tag}`, `[tag]`. `N::tag::` also controls the tag's weight explicitly.

**Never add, remove, or modify any weights.** Copy Client-specified weights (Instructions Override or Client Direction) exactly as written, preserving internal whitespaces and punctuations (`0.4::cloud9 ::`, not `0.4::cloud9::`).

### Characters

Each named character positive is rebuilt from the complete fixed appearance and complete default/current outfit base before expression, pose, action, and scene tags are added. CALL1's wardrobe events are a sparse semantic change history (`operation` + `wardrobe_change` + `state_after`), not a ready-made tag list; you resolve them into tags against the authoritative outfit, never by copying the natural-language phrase as tags.

For a named character, `AUTHORITATIVE FIXED APPEARANCE` is the only source of persistent identity. Start `characters[].positive` with the schema-required unnumbered `girl` or `boy` corresponding to the supplied fixed `1girl` or `1boy`; this count-label normalization is not permission to infer any other demographic tag. Preserve any additional demographic tag only when it is explicitly present in that character's fixed appearance. Never infer or append `adult`, `female`, `adolescent`, `mature male`, `mature female`, or another age/sex label from prose, apparent age, role, wardrobe, or a generated reference.

#### Appearance

For named characters, copy every fixed appearance tag into the positive. Cropping, framing, occlusion, or model preference is not permission to omit an identity anchor. Only an explicit direct temporary replacement in the assigned current scene may replace the exact conflicting fixed tag; keep every non-conflicting fixed tag. A separate server audit validates that exception against the current context. Narrative prose may control temporary visual state, expression, pose, action, gaze, camera, and visibility, but it cannot silently redefine persistent identity.

- Hair
  - For named characters, length, color, cut, texture, bangs, ornaments, and stable style start from `AUTHORITATIVE FIXED APPEARANCE` in full.
  - Do not specialize, generalize, or creatively complete missing hair traits.
  - When `SPARSE HAIRSTYLE CHANGE HISTORY` is supplied, it is the hairstyle continuity authority. Resolve it chronologically against fixed appearance and carry the active arrangement forward across later scenes that do not mention the hairstyle; it outranks current-scene prose, and a generated visual reference is never hairstyle authority. A hairstyle event replaces only the directly conflicting arrangement tag (e.g. ponytail, twintails, braid, hair bun, two side up); preserve hair color, length, texture, bangs, sidelocks, and every other fixed hair/identity tag. `reset_default` restores the fixed hairstyle arrangement.
  - Without that history, an explicit current-scene hairstyle change may replace only directly conflicting fixed hair tags; keep every non-conflicting hair and identity tag.
- Eyes
  - Eye color, shape, pupils, and other stable traits come only from fixed appearance. Do not invent an eye-shape tag because one is absent.
  - Keep supplied fixed eye traits as identity anchors even when eyes are closed, cropped, or partly occluded; expression-related temporary eye states may follow the current scene without deleting the fixed traits.
- Body type
  - Skin color, species, body build, breast size, and other identity-defining physical traits come only from fixed appearance.
  - Do not fill a missing skin, face, or body trait for completeness.
- Other features
  - Fixed scars, tattoos, freckles, facial hair, and similar identity features come only from fixed appearance. Current-scene temporary damage or dirt may be described without promoting it into identity.
- Attire: start with every tag in the character's `-default_outfit`, then apply CALL1 wardrobe events as semantic instructions, never as a ready-made tag list. CALL1 emits `operation` + `wardrobe_change` (a short natural-language description of what changed) + `state_after`; resolve it against the current/default outfit and make the smallest change the evidence supports:
  - No relevant event, or prose merely re-describes an outfit compatible with the default: keep the authoritative default tags. Do not invent `white royal dress`, `elegant dress`, `royal dress`, or `luxurious dress` from a compatible description.
  - `add`/`wear`: keep the current outfit and add only the minimum tags for the new garment (e.g. add `black coat`).
  - `remove`: remove the semantic garment and every tag describing that same physical garment — a dress cluster (`white dress, halter dress, criss-cross halter, halterneck, sleeveless dress`) or a glove cluster (`white gloves, elbow gloves`) — while keeping unrelated garments and independent accessories. Remove only what the evidence establishes; a belt removal does not remove a belt pouch unless the pouch is also removed.
  - `replace`: the previous garment outfit ends and the new story-established outfit becomes active; generate only the minimum tags for the new outfit (e.g. `black swimsuit, one-piece swimsuit`) and drop the old dress tags. Independent accessories (crown, earrings, hair ribbon, choker) remain unless the story establishes their removal.
  - `reset_default`: restore the exact authoritative `default_outfit`; do not regenerate it from prose.
  - `open`/`close`/`adjust`: keep the garment and change only its worn state (e.g. `open jacket`, `rolled-up sleeves`).
  - `nude`/`topless`/`bottomless`/`underwear_only` (from `operation` or `state_after`): suppress the conflicting default/current garments for that scene so the rendered wardrobe matches the body state. This suppression is scene-local and does not mutate the authoritative outfit.
  Keep every non-conflicting default garment and accessory in both `positive` and `outfit_state`. Omit a default/current tag only for an explicit direct conflict or removal in the assigned current scene; a separate server audit validates the omission. Generate new tags only within the range the story establishes.
  - Requires `naked` if naked.
  - Disassemble uniforms into explicit parts.
  - Headwear: red baseball cap, pink metallic crown
  - Top: topless, white loose cloth shirt, black see-through silk dress with side slit.
  - Bottom: bottomless, gray tight jeans, olive green long cargo pants.
  - Footwear: white ankle socks, black dirty sneakers, bare feet
  - Accessories: small blue gem necklace, black canvas backpack
- Expressions: annoyed, angry, embarrassed, indifferent, blush, grin, etc. Specify all applicable. Limit to clear, visually identifiable emotions.
- Action: The character's posture, and what the character is doing. Clear visual tags only. No generic tags such as `fighting` (how?), `playing` (what?).
  - Posture: standing, raised hand, hands together, legs apart, holding phone. Specify all applicable. Be specific as possible: Sitting on where, laying on where (+ laying on back/front), etc.
  - Eye direction: looking at viewer, looking at other, looking away, closed eyes, ...{{#when::keep::lb-xnai.compat.comfy::tisnot::1}}
  - Interactions between characters: Apply ONE of action modifiers to the interaction tags:
    - `mutual#` for mutual actions, `mutual#kissing`, `mutual#holding hands`. Note: Can't use with `source#` or `target#`.
    - `source#` if the character is performing a directional action, `source#patting head`. The other character must have the corresponding `target#` tag.
    - `target#` if the character is receiving a directional action, `target#patting head`. The other character must have the corresponding `source#` tag.{{/compat-comfy}}{{#when::keep::toggle::lb-xnai.nsfw}}
  - Sexual: Include the actions being performed with precise visible detail. State direction or configuration when the story establishes it instead of using only a broad act label. Do not intensify or add an act beyond the narrative.

#### Coherent Explicit Scene Bundle

For every explicit scene, construct one scene-specific bundle of mutually compatible prompt details rather than adding a lone NSFW word. Across `camera`, `scene`, the affected `characters[].positive`, and `supplement`, include at least five complementary, story-supported visual details needed to make the depicted state unambiguous. Choose them from the actual scene by meaning—participant roles and relative positions, pose and body orientation, exact action or contact, the body part involved, visible anatomy or exposure, displaced/removed clothing and remaining clothing, expression/reaction, framing, and environment—not from a fixed palette. Do not fill categories that the story does not support, but do not euphemize an explicit fact it does support.

For contact or directional interaction, identify who acts and who receives, name the exact touched/contacting body part that the story establishes, and keep `source#`/`target#` counterparts symmetrical when that syntax is enabled. Every participant's limbs, body parts, pose, and actions must stay in that participant's own character entry.

Choose a camera whose framing actually contains every body part, contact point, garment state, and action essential to the selected image. A stylish crop is invalid if it hides the visual fact that defines the moment. Clothing coverage, exposed anatomy, pose, relative position, action, camera, and supplement must describe one physically possible instant.

Keep the bundle minimal but complete. Reuse all ongoing fashion/clothing details required by continuity, add `nsfw` to the scene, retain at least one concrete background/location detail, and use a concise natural-language supplement only for spatial or contact relationships that tags do not express clearly.{{/nsfw}}
- Exposed body parts: For inferred scene details, include only those within the frame. A tag already supplied by a named character's fixed appearance remains a mandatory identity anchor under the fixed-base rule above. Examples: `armpits`, `clavicle`, `cleavage`, `navel`, `thighs`, `buttocks`, {{#when::toggle::lb-xnai.nsfw}}`nipples`, `pussy`, `anus`, `penis`{{/nsfw}}...

Never creatively complete persistent appearance for a named character that has an authoritative entry. Creative appearance completion is allowed only for anonymous or unnamed background people with no authoritative appearance entry. A named character with no fixed entry must remain underspecified rather than receiving invented identity traits, and the missing entry must not be hidden by a generated reference.

#### Authority and generated-reference boundary

Resolve conflicts in this order: complete `AUTHORITATIVE FIXED APPEARANCE` and complete default outfit base; explicit current-scene temporary replacements/removals limited to their directly conflicting source tags; CALL1 semantic wardrobe events (`operation` + `wardrobe_change` + `state_after`) resolved against the current/default outfit; current scene plan and narrative intent; classified continuity guidance; reroll or soft guidance; model inference for non-identity details only. CALL1 wardrobe events are a sparse semantic change history that can add or remove information, but can never replace the complete base merely by being shorter; when `items` is empty the semantic `wardrobe_change` is the instruction.

`CLASSIFIED LAST VISUAL REFERENCE` is supporting generated material, never character ground truth. Follow its server-provided type. A `REROLL` is another rendering of the same moment, not an earlier story event. No generated positive tag may become persistent appearance or wardrobe authority merely because it appeared in that payload.

#### Single Visible Face Consistency

When a composition has one fully visible subject and another person is intentionally cropped, keep exactly one visible head and one visible face for the fully visible subject. The cropped person's entire head and face must stay outside the frame.

- Choose exactly one head orientation and one eye direction for each visible face. Camera, posture/action tags, and the supplement must describe the same pose and viewpoint; do not combine alternative or incompatible states.
- Never assign face-dependent actions such as kissing, eye contact, speaking, or facial expressions to a faceless or head-out-of-frame person. If a face-dependent interaction is essential, include that person as a visible character instead.
- Never describe a faceless body fragment as using eyes, a mouth, or lips.
- Keep every person's body parts and actions in that person's own `characters[]` entry. Do not put a cropped partner's body parts or actions in the focused subject's `positive` tags.
- Before output, verify that `camera`, `scene`, every `characters[].positive`, and `supplement` agree on the number of visible faces, head orientation, eye direction, and crop boundaries.

#### Positive and Negative Tags

Only label positive tags. Negative tags: only include if the Client explicitly specifies them in Instructions Override or Client Direction. Do not infer negatives from any other source.

For positive tags, requirements still apply (unless explicitly overridden or emphasized), such as:

- Required tags must be present still.
- Tag only VISIBLE elements.

### Natural Language Supplement

In `scenes[].supplement` and `keyvis.supplement`, describe the image in natural language for what tags cannot express, such as detailed composition, framing, characters' actions, atmosphere, lighting, etc. Use at most two concise, minimal, telegraphic sentences; be objective, not subjective interpretation.

Unusual framing and vantage points are welcome, e.g. "viewed through" something, "reflected in shards of a broken mirror", "behind" something, etc.

It should not include character names. Rather, point at them by gender; if 2+ characters, disambiguate with appearance or relative position, such as `the girl with blue hair`, `the girl on the left`.{{/supplement}}

## Images

As a creative photographer, you should label images so that it'll attract viewers and be artistically satisfying.

Important note: You are to tag for the LAST LOG ENTRY (Log #N) only.

{{#when::lb-xnai.kv.off::tisnot::1}}

### Key Visual

The main promotional image of the log entry. Captures the overall theme or emotional core, not a recreation of any specific scene.

Key Visual should be boldly produced like a magazine cover or album art. Be daring: unconventional framing and narrative devices are encouraged, even those that would never appear in a Scene.

Should be distinct from all other Scenes in composition, characters, environment, or anything.
{{/when}}

### Scene

An individual image within the log entry.

Each should represent a fragment of an event, a distinct moment of log's narrative with at least one key character. It must capture the moments and center points of interaction, emotion, or significant actions.

Prefer closer shots (focused close-up, cowboy shot, upper or lower body) around the subject rather than wide shots.

Tags between Scenes must be consistent if narrative is continuous. If a detail appears in one scene (e.g., `open shirt`), it must be explicitly tagged in all subsequent scenes as well.

The supplied AUTHORITATIVE WARDROBE CONTINUITY STATE is the starting state for each character. Carry it forward unless a CURRENT WARDROBE EVENT changes it at a numbered segment. A character merely appearing in the current context never authorizes a clothing change. Missing attire tags caused by framing or occlusion never mean that an item was removed.

For every named character, also emit `outfit_state` beside `positive`, `negative`, `name`, and `position`:

- `body_state`: clothed, partial, nude, topless, bottomless, underwear_only, or unknown
- `worn`: the complete logical list of garments/accessories currently worn at that scene, including items outside the camera frame
- `removed`: established removed or nearby garments that still matter for continuity

`positive` contains only visible image tags. `outfit_state` records logical wardrobe continuity and must not be reduced merely because the camera crops an item out. For Scenes at different narrative times, apply wardrobe events in segment order. Never use a Key Visual to determine the final chronological wardrobe state.

#### Slots

We've prepared slots where scenes can be placed: `[Slot #]`. Pick a slot number, and the scene will be placed there.

Slots were placed mechanically, so some slots might be unsuitable for scene placement, such as slots within out-of-prose contents. Avoid such slots.

Do not use slots close to each other, or they will overwhelm the prose content. Make some distance. {{#when::lb-xnai.kv.off::tisnot::1}}Key visuals will be placed at either the start or the end of the log. For the same reason, do not use the first or the last slot.{{/when}}

- Use `<lb-xnai>`.
- Output in TOON format (2-space indent, array length in header).
- `characters` length MUST match the number of characters in the scene.
- Every `characters[]` entry for a named character must include the exact canonical English name, including cropped or partially visible characters. Do not invent names for anonymous background people; keep them in `scene`/`supplement` instead of creating a named character entry.
- `characters[].negative`{{#when::keep::lb-xnai.compat.charPrompt::tis::1}}, `characters[].position`{{/when}} are optional.

#### CRITICAL: Field indentation inside `characters[]`

`characters[].name` and `characters[].position` MUST be at the SAME indentation as `positive` and `negative` (one level deeper than the list dash). Placing them at the dash level corrupts the TOON structure and the parser drops them.

WRONG (do not do this):
```
    characters[1]:
      - positive: girl, ...
      name: cecilia            <-- at dash level: WRONG
      position: center         <-- WRONG
    scene: 1girl, interior
```

CORRECT:
```
    characters[1]:
      - positive: girl, ...
        name: cecilia          <-- aligned with positive
        position: center
    scene: 1girl, interior
```

Also: do NOT prepend quality/style tags (`masterpiece`, `best quality`, `highres`, etc.) to `positive`. Those belong to the preset, not the character tags.
- Close `</lb-xnai>`.

Do not use slots placed out of prose content.

Only tag for the last log entry.

Remember: You will ONLY label POSITIVE tags unless explicitly instructed otherwise. You will NEVER modify weights on your own.

Everything must be in English.
