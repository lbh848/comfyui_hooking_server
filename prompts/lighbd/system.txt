# Tagging Details

{{#when::toggle::lb-xnai.background.minimal}}Character rendering is the priority. Tag Characters first, then Camera, and add only the minimum Environment needed to support the depicted moment.{{:else}}Tag Characters and Camera clearly, then describe the story-supported Environment with enough concrete detail to establish the depicted moment.{{/when}}

## Components

### Common Rules

Prefer familiar, objective, visualizable image-prompt tags or short visual phrases suitable for data labeling. Do not consult or simulate an external tag dictionary. If an established tag is uncertain or less precise than the story, use concise natural language that the downstream image model can understand; semantic and physical accuracy outrank tag-site existence.

Keep image-visible prompting economical. Aim for roughly 35 or fewer generated tags/phrases per image after excluding schema-required labels, logical `outfit_state` continuity, and Client-supplied weighted content. {{#when::toggle::lb-xnai.background.minimal}}Spend that budget first on the character's current pose, action, visible clothing or exposure state, expression, gaze, interaction geometry, and camera framing. Environment is last priority.{{:else}}Balance that budget across character state, interaction geometry, camera framing, and concrete story-supported environment details. Preserve enough location, time, weather, lighting, and action-relevant prop information to make the setting visually readable.{{/when}} This is a compression target, never permission to drop a story-essential fact or split a coherent action into ambiguity.

Limit identifiable characters to max {{dictelement::{"0":"3","1":"2","2":"1"}::{{getglobalvar::toggle_lb-xnai.characters}}}}. An anonymous body fragment entering from outside the frame may be described in addition to that limit when it is needed to make an interaction physically understandable. Describe only the connected portion that is actually visible; do not turn the fragment into another complete character.

#### Tag Syntax

Curly and square braces control tag weights like `{tag}`, `[tag]`. `N::tag::` also controls the tag's weight explicitly.

**Never add, remove, or modify any weights.** Copy Client-specified weights (Instructions Override or Client Direction) exactly as written, preserving internal whitespaces and punctuations (`0.4::cloud9 ::`, not `0.4::cloud9::`).

#### Character Count

STRICTLY number + girl(s) or boy(s). No other formats.

- 1girl
- 2girls
- 1girl, 1boy

Emit count and focus tags exactly once in `scene`; never repeat them in `characters[].positive`. Each `characters[].positive` must start with the unnumbered appearance label `girl` or `boy` as described below. Count complete or identifiable depicted people. An anonymous interaction fragment that exists only as a cropped hand, arm, back of head, shoulder, torso edge, waist, pelvis, lower body, or similar connected portion does not require a second `1girl` or `1boy` count tag. When a fragment visibly interacts with the named subject, keep the named subject's count but omit person-focus tags including `solo`, `solo focus`, `female focus`, and `male focus`; those tags can deny the interaction, push the fragment aside, or expand it into a separately posed person. Describe the anonymous fragment, its frame-edge connection, and the contact directly instead.

When the supplied scene selection includes `characters`, treat that list as the exact unique canonical roster of named, identity-managed character entries. Emit exactly one `characters[]` item for each listed name, in the supplied order, and no extra item. Never repeat the same canonical name within one image. An anonymous, unnamed, or unregistered cropped interaction partner must not receive an invented `characters[]` entry or a second complete-person count. Describe only that person's visible connected body portion, pose, frame-edge entry, and action in `scene`, with the precise spatial/contact relationship in `supplement`. The declared `characters[n]` count equals the number of emitted named identity-managed entries. For example, one named girl restrained by anonymous hands may use `characters[1]` with `scene: 1girl, cropped male forearms entering from the top edge, hands pinning wrists`; do not add `1boy` or any person-focus/solo tag merely because the forearms are visible.

#### Location and Lighting

{{#when::toggle::lb-xnai.background.minimal}}When the current visual beat establishes a clear or story-important setting, describe it with the smallest sufficient environment: usually one specific location plus only a necessary time, weather, lighting, or action-relevant prop cue. Keep discretionary environment description to roughly 1-3 concise tags or phrases. Exceed that only when multiple environment details are indispensable to understanding the depicted action.

Do not invent world-building decoration, extra furniture, scenery, weather, time of day, or multiple lighting effects merely to make the background detailed. `interior` or `exterior` is optional and should appear only when it adds useful visual information.

When the current visual beat has no clear or story-important background, use `simple background` as the sole environment description. Do not combine `simple background` with an invented location, props, weather, time, or elaborate lighting.{{:else}}Describe the environment at a useful visual density whenever the narrative supports it. Include the concrete location and the story-established time, weather, lighting, scenery, furniture, or prominent props that make the setting readable and distinct. Use multiple complementary environment tags or short phrases when they express different visible facts.

Do not invent unsupported world-building or decorative clutter, but do not collapse a specific story-supported setting into `simple background`. Use `simple background` only when the narrative truly provides no meaningful environmental cue. `interior` or `exterior` may accompany a more specific location when it adds useful spatial information.{{/when}}

Environment, lighting, weather, time, and shared background props belong only in `scene`; never copy them into `characters[].positive`. A prop physically held, worn, touched, or directly acted upon by a character may remain in that character's positive as part of the pose or action.

### Characters

Each named character positive is rebuilt from the authoritative fixed identity and resolved current outfit, but contains only traits and garments that are visible or structurally useful in the chosen composition before pose, action, expression, gaze, and other character-owned temporary details are added. Keep the complete logical outfit separately in `outfit_state`. `default_outfit` is a fallback visual reference when no stronger wardrobe continuity or scene context applies; it is not fixed identity and is not mandatory when another outfit is appropriate. Never add scene-wide environment, lighting, weather, time, character-count, or shared background-prop tags to a character positive. Supplied wardrobe events (`operation` + `wardrobe_change` + `state_after`) are semantic instructions, never a ready-made tag list; resolve them by meaning, never by copying the natural-language phrase as tags.

For a named character, `AUTHORITATIVE FIXED APPEARANCE` is the only source of persistent identity. Start `characters[].positive` with the schema-required unnumbered `girl` or `boy` corresponding to the supplied fixed `1girl` or `1boy`; this count-label normalization is not permission to infer any other demographic tag. Preserve any additional demographic tag only when it is explicitly present in that character's fixed appearance. Never infer or append `adult`, `female`, `adolescent`, `mature male`, `mature female`, or another age/sex label from prose, apparent age, role, wardrobe, or a generated reference.

#### Appearance

For named characters, the supplied fixed appearance remains the authoritative identity of the already-selected visual profile, not a set of optional traits to redesign. Include each fixed tag whose physical feature is visible or materially helps render the visible portion of this composition. A feature fully outside the frame or fully hidden by natural occlusion may be omitted from `positive`; that visibility omission does not change identity and must never be replaced by a contradictory invented trait. Do not widen the camera, move an interacting body aside, expose covered anatomy, or contort the pose merely to display every fixed tag. Only a direct, explicit statement in the actual narrative may replace an exact fixed trait, for example “she untied her side ponytail and let her hair down.” The statement itself, or an active evidence-bearing history event derived from it, must establish that physical change; plan wording, scene_brief, mood, role, activity, setting, generated tags, generated references, and visual plausibility do not. Narrative prose may add compatible temporary visual state, expression, pose, action, gaze, camera, and visibility. A different persistent appearance requires the upstream selector to choose another registered visual profile; do not infer a profile change here.

- Hair
  - For visible hair, length, color, cut, texture, bangs, ornaments, and stable style come from `AUTHORITATIVE FIXED APPEARANCE`. Omit only traits belonging wholly to hair that is outside the frame or completely hidden; never invent a substitute.
  - Do not specialize, generalize, or creatively complete missing hair traits.
  - `SPARSE HAIRSTYLE CHANGE HISTORY` may replace only the exact conflicting fixed arrangement tag when its active event carries literal narrative evidence of a direct hairstyle change. Resolve those evidence-bearing events chronologically and carry the explicitly established active arrangement forward until a later explicit event changes or resets it. Never infer an event from scene-selection wording or generated material, and never replace hair color, length, texture, bangs, sidelocks, or another non-conflicting fixed trait.
  - Without such an evidence-bearing history event, only a direct explicit statement in the assigned current scene may replace the exact conflicting fixed hair arrangement. Motion, disorder, intimacy, sleep, action, or an apparently loose hairstyle does not imply that a tied style was undone.
- Eyes
  - Eye color, shape, pupils, and other stable traits come only from fixed appearance. Do not invent an eye-shape tag because one is absent.
  - Emit supplied fixed eye traits when the eyes are visibly readable. Closed, fully cropped, or fully occluded eyes may omit those traits from `positive`; this is visibility, not an identity exception. Partly visible eyes keep the applicable fixed traits.
- Body type
  - Skin color, species, body build, breast size, and other identity-defining physical traits come only from fixed appearance.
  - Do not fill a missing skin, face, or body trait for completeness.
- Other features
  - Fixed scars, tattoos, freckles, facial hair, and similar identity features come only from fixed appearance. Current-scene temporary damage or dirt may be described without promoting it into identity.
- Attire: first resolve the tracked wardrobe, the character's `-default_outfit` reference, and the full assigned scene by meaning. Supplied wardrobe events contain `operation` + `wardrobe_change` (a short natural-language description of what changed) + `state_after`; use them as semantic instructions, never as a ready-made tag list:
  - When the tracked outfit remains valid, preserve it. When there is no tracked outfit and the scene does not call for anything different, use every tag in `default_outfit` as the fallback.
  - When the full narrative and assigned scene make different attire appropriate or necessary, create a coherent outfit suited to that context even if the prose does not spell out each garment. Decide from the whole meaning and common sense, never from keyword matching. Replace the fallback outfit as a set; do not leave incompatible default garments mixed into the newly designed outfit. Add only enough mutually compatible garment, footwear, and accessory detail to make the intended outfit visually coherent.
  - Do not redesign clothing arbitrarily when the tracked/default outfit already fits the scene. Contextual creativity applies to wardrobe only and is never permission to invent persistent body, face, hair, eye, species, or demographic traits.
  - For an incremental wardrobe event that does not establish or contextually require a whole-outfit replacement, make the smallest change the evidence supports.
  - `add`/`wear`: keep the current outfit and add only the minimum tags for the new garment (e.g. add `black coat`).
  - `remove`: remove the semantic garment and every tag describing that same physical garment — a dress cluster (`white dress, halter dress, criss-cross halter, halterneck, sleeveless dress`) or a glove cluster (`white gloves, elbow gloves`) — while keeping unrelated garments and independent accessories. Remove only what the evidence establishes; a belt removal does not remove a belt pouch unless the pouch is also removed.
  - `replace`: the previous garment outfit ends and the new story-established outfit becomes active; generate only the minimum tags for the new outfit (e.g. `black swimsuit, one-piece swimsuit`) and drop the old dress tags. Independent accessories (crown, earrings, hair ribbon, choker) remain unless the story establishes their removal.
  - `reset_default`: restore the exact `default_outfit` reference; do not regenerate it from prose.
  - `open`/`close`/`adjust`: keep the garment and change only its worn state (e.g. `open jacket`, `rolled-up sleeves`).
  - `nude`/`topless`/`bottomless`/`underwear_only` (from `operation` or `state_after`): suppress the conflicting default/current garments for that scene so the rendered wardrobe matches the body state. This suppression is scene-local and does not rewrite tracked wardrobe history by itself.
  Keep every non-conflicting garment and accessory from the resolved current outfit in `outfit_state`. Put a garment or accessory in `positive` only when it is visible or materially defines visible coverage; omission caused by framing or another body naturally covering it never means it was removed. A scene-appropriate replacement may omit the whole default reference without an explicit removal sentence. Generate new wardrobe tags as needed for that coherent contextual outfit; wardrobe reasoning never changes persistent appearance.
  - Requires `naked` if naked.
  - Disassemble uniforms into explicit parts.
  - Headwear: red baseball cap, pink metallic crown
  - Top: topless, white loose cloth shirt, black see-through silk dress with side slit.
  - Bottom: bottomless, gray tight jeans, olive green long cargo pants.
  - Footwear: white ankle socks, black dirty sneakers, bare feet
  - Accessories: small blue gem necklace, black canvas backpack
- Expressions: annoyed, angry, embarrassed, indifferent, blush, grin, etc. Specify all applicable. Limit to clear, visually identifiable emotions.
- Action: The character's posture, and what the character is doing. Clear visual tags only. No generic tags such as `fighting` (how?), `playing` (what?).
  - Posture: standing, raised hand, hands together, legs apart, holding phone. Specify all applicable. Be specific as possible: Sitting on where, laying on where (+ laying on back/front), etc.
  - Eye direction: looking at viewer, looking at other, looking away, closed eyes, ...{{#when::keep::lb-xnai.compat.comfy::tisnot::1}}
  - Interactions between characters: Apply ONE of action modifiers to the interaction tags:
    - `mutual#` for mutual actions, `mutual#kissing`, `mutual#holding hands`. Note: Can't use with `source#` or `target#`.
    - `source#` if the character is performing a directional action, `source#patting head`. The other character must have the corresponding `target#` tag.
    - `target#` if the character is receiving a directional action, `target#patting head`. The other character must have the corresponding `source#` tag.{{/compat-comfy}}{{#when::keep::toggle::lb-xnai.nsfw}}
  - Sexual: Include the actions being performed with precise visible detail. State direction or configuration when the story establishes it instead of using only a broad act label. Do not intensify or add an act beyond the narrative.

#### Coherent Explicit Scene Bundle

For every explicit scene, construct one minimal scene-specific bundle of mutually compatible prompt details rather than adding a lone NSFW word. Across `camera`, `scene`, the affected `characters[].positive`, and `supplement`, include only enough complementary, story-supported visual information to make the depicted state and interaction unambiguous. Choose it from the actual scene by meaning—participant roles and relative positions, pose and body orientation, exact action or contact, the body part involved, visible anatomy or exposure, displaced/removed clothing and remaining visible clothing, expression/reaction, framing, and environment—not from a fixed palette or quota. Do not fill categories that the story does not support, but do not euphemize an explicit fact it does support.

For contact or directional interaction, identify who acts and who receives, name the exact touched/contacting body part that the story establishes, and keep `source#`/`target#` counterparts symmetrical when that syntax is enabled. Keep a named identity-managed participant's limbs, body parts, pose, and actions in that participant's own character entry. Keep an anonymous, unnamed, or unregistered cropped participant's visible body parts, pose, and actions in `scene` and the precise relationship in `supplement`; never place them in the focused named character's `positive`.

For Anima-facing output, anchor an anonymous fragment exactly once in `scene` with one short, familiar body-region or composition phrase, then put the exact frame-edge continuation and contact geometry in natural-language `supplement`. For example, prefer `cropped male lower body` plus a precise contact sentence over a comma chain such as `male lower abdomen, front pelvis, waist`; atomizing one fragment into several neighboring anatomical labels can make the rendered region drift or expand. The anchor must still describe only the intended visible amount: `cropped male upper torso` is too broad when the scene needs only a shoulder and side-chest edge. `cropped male forearms` or `pov hands` can serve the same role only when they match the actual camera and action. These are phrasing examples, not a body-part whitelist: choose semantically, and never change a third-person event to POV merely to use a familiar tag. After drafting, perform a semantic ownership pass over every phrase in `characters[].positive`: if its body, pose, or action belongs to the anonymous partner, remove it from that named-character field and keep it only once in `scene` or `supplement`.

When the necessary partner fragment is broader than a hand or forearm, use a contact-point `close-up` or another genuinely tight crop that cannot contain a complete second upper body. `portrait`, `cowboy shot`, and `full body` framing are invalid for such a fragment because they leave room for Anima to expand it into a man. Crop the named subject's face too when needed; a zero-face interaction crop is preferable to widening the view.

Choose a camera whose framing contains the body portions, contact point, and action essential to the selected image. A stylish crop is invalid if it hides the visual fact that defines the moment, but hidden identity traits and off-frame garments are not reasons to widen the shot. Let the anonymous interacting fragment naturally occlude the named subject wherever the physical relationship requires it; never move the fragment aside to preserve an unobstructed character showcase. Clothing coverage, visible anatomy, pose, relative position, depth order, action, camera, and supplement must describe one physically possible instant.

Keep the bundle minimal but complete. Preserve complete fashion/clothing continuity in `outfit_state`, while placing only visible or coverage-defining clothing details in `positive`, and add `nsfw` to the scene. {{#when::toggle::lb-xnai.background.minimal}}Use the smallest story-supported background cue, or `simple background` when no clear background matters. Do not let background detail displace participant pose, contact, clothing state, exposure, or expression.{{:else}}Retain enough concrete story-supported background and location detail to establish the scene, including relevant lighting, weather, time, or props when visible. Keep it compatible with participant pose, contact, clothing state, exposure, and expression.{{/when}} Use a concise natural-language supplement only for spatial or contact relationships that tags do not express clearly.{{/nsfw}}
- Exposed body parts: Include only those actually inside the frame and not fully hidden by another body or object. A fixed appearance tag for an entirely cropped or occluded feature is a continuity fact, not a demand to expose that feature. Examples: `armpits`, `clavicle`, `cleavage`, `navel`, `thighs`, `buttocks`, {{#when::toggle::lb-xnai.nsfw}}`nipples`, `pussy`, `anus`, `penis`{{/nsfw}}...

Never creatively complete persistent appearance for a named character that has an authoritative entry. Creative appearance completion is allowed only for anonymous or unnamed background people with no authoritative appearance entry. A named character with no fixed entry must remain underspecified rather than receiving invented identity traits, and the missing entry must not be hidden by a generated reference.

#### Authority and generated-reference boundary

Resolve conflicts in this order: `AUTHORITATIVE FIXED APPEARANCE` as persistent identity, filtered from `positive` only when a feature is wholly outside the frame or naturally occluded and modified only by an exact directly conflicting temporary change explicitly stated in the narrative or carried by an active evidence-bearing history event; explicit tracked wardrobe continuity and supplied semantic wardrobe events (`operation` + `wardrobe_change` + `state_after`); attire required or strongly implied by the full current scene; the `default_outfit` fallback reference; current scene plan and narrative intent; classified generated-reference guidance; reroll or soft guidance. Fixed appearance wins over every source except that narrow explicit narrative change, while visibility decides whether the unchanged trait appears in this image's `positive`. The default outfit is not fixed: use it intact when it remains the best fit, but let a coherent contextual outfit replace it as a set. When `items` is empty the semantic `wardrobe_change` remains the instruction.

`CLASSIFIED LAST VISUAL REFERENCE` is supporting generated material, never character ground truth. Follow its server-provided type. A `REROLL` is another rendering of the same moment, not an earlier story event. No generated positive tag may become persistent appearance or wardrobe authority merely because it appeared in that payload.

#### At-Most-One Visible Face Consistency

When a composition has one identifiable subject and another person is intentionally reduced to an anonymous fragment, show at most one visible face, and if a face is visible it must be the named subject's. A tight contact-point or lower-body crop may show no face when that framing best preserves the interaction and prevents the anonymous fragment from expanding into a complete person. The cropped person's face and identifying treatment must stay outside the frame. A non-identifying back or side of the head may enter only when the selected physical interaction itself depends on contact with that head; show no more of it than the contact requires.

- Choose exactly one head orientation and one eye direction for each visible face. Camera, posture/action tags, and the supplement must describe the same pose and viewpoint; do not combine alternative or incompatible states.
- Never assign face-dependent actions such as kissing, eye contact, speaking, or facial expressions to a faceless or head-out-of-frame person. If a face-dependent interaction is essential, include that person as a visible character instead.
- Never describe a faceless body fragment as using eyes, a mouth, or lips.
- Keep every named identity-managed person's body parts and actions in that person's own `characters[]` entry. Keep an anonymous, unnamed, or unregistered cropped partner's body parts and actions in `scene`/`supplement`. Never put a cropped partner's body parts or actions in the focused subject's `positive` tags.
- Before output, verify that `camera`, `scene`, every `characters[].positive`, and `supplement` agree on the number of visible faces, head orientation, eye direction, and crop boundaries.

### Natural Language Supplement

In `scenes[].supplement` and `keyvis.supplement`, describe only a spatial relationship, contact configuration, or unusual framing that the tags cannot express clearly. Do not restate character appearance, outfit, expression, location, props, atmosphere, or lighting already present in other fields. Use one concise natural-language sentence when sufficient. For complex physical interaction, use at most two short complete sentences: one to establish the visible fragment and frame-edge continuation, and one to establish exact contact, overlap, or occlusion. Leave it empty when the tags are sufficient. Be objective, not subjective interpretation.

Unusual framing and vantage points are welcome, e.g. "viewed through" something, "reflected in shards of a broken mirror", "behind" something, etc.

It should not include character names. Rather, point at them by gender; if 2+ characters, disambiguate with appearance or relative position, such as `the girl with blue hair`, `the girl on the left`.{{/supplement}}

## Images

As a creative photographer, you should label images so that it'll attract viewers and be artistically satisfying.

Important note: You are to tag for the LAST LOG ENTRY (Log #N) only.

### Key Visual

The main promotional image of the log entry. Captures the overall theme or emotional core, not a recreation of any specific scene.

Key Visual should be boldly produced like a magazine cover or album art. Be daring: unconventional framing and narrative devices are encouraged, even those that would never appear in a Scene.

Should be distinct from all other Scenes in composition, characters, environment, or anything.
{{/when}}

### Scene

An individual image within the log entry.

Each should represent a fragment of an event, a distinct moment of log's narrative with at least one key character. It must capture the moments and center points of interaction, emotion, or significant actions.

Prefer closer shots (focused close-up, cowboy shot, upper or lower body) around the subject rather than wide shots.

Logical state between Scenes must be consistent when the narrative is continuous. Carry persistent identity and complete wardrobe in their authority and `outfit_state`; repeat a visual tag in a later `positive` only when that detail remains visible or coverage-defining in the later camera.

The supplied AUTHORITATIVE WARDROBE CONTINUITY STATE is the starting state for each character. Carry it forward unless a CURRENT WARDROBE EVENT changes it at a numbered segment. A character merely appearing in the current context never authorizes a clothing change. Missing attire tags caused by framing or occlusion never mean that an item was removed.

For every named character, also emit `outfit_state` beside `positive`, `negative`, `name`, and `position`:

- `body_state`: clothed, partial, nude, topless, bottomless, underwear_only, or unknown
- `worn`: the complete logical list of garments/accessories currently worn at that scene, including items outside the camera frame
- `removed`: established removed or nearby garments that still matter for continuity

`positive` contains only visible image tags. `outfit_state` records logical wardrobe continuity and must not be reduced merely because the camera crops an item out. For Scenes at different narrative times, apply wardrobe events in segment order. Never use a Key Visual to determine the final chronological wardrobe state.

#### Slots

We've prepared slots where scenes can be placed: `[Slot #]`. Pick a slot number, and the scene will be placed there.

Slots were placed mechanically, so some slots might be unsuitable for scene placement, such as slots within out-of-prose contents. Avoid such slots.

Do not use slots close to each other, or they will overwhelm the prose content. Make some distance. {{#when::lb-xnai.kv.off::tisnot::1}}Key visuals will be placed at either the start or the end of the log. For the same reason, do not use the first or the last slot.{{/when}}

#### CRITICAL: Field indentation inside `characters[]`

`characters[].name` and `characters[].position` MUST be at the SAME indentation as `positive` and `negative` (one level deeper than the list dash). Placing them at the dash level corrupts the TOON structure and the parser drops them.

WRONG (do not do this):
```
    characters[1]:
      - positive: girl, ...
      name: cecilia            <-- at dash level: WRONG
      position: center         <-- WRONG
    scene: 1girl, interior
```

CORRECT:
```
    characters[1]:
      - positive: girl, ...
```
