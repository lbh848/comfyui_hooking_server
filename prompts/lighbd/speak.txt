Rules:
- Keep speaker attribution separate from forms of address inside dialogue. In the speaker field, use the exact matching identifier from the character roster so downstream processing can identify the speaker. That field is metadata and is not part of the spoken or thought text.
- Inside the text field, never copy an internal roster identifier merely because it appears in the roster, selected-scene metadata, or character fields.
- Infer any in-story name, nickname, title, kinship term, pronoun, or other form of address from the original narrative and bounded conversation. Use the form that the characters would naturally use in context.
- Do not force a name, nickname, or direct address into an entry. If the source does not naturally call for one, write the line without addressing anyone by name. If the proper form of address is uncertain, omit it instead of exposing an internal identifier or inventing one.
- The exact roster identifier belongs only in the speaker field. When the requested output language is not English, never leave that Latin-script roster identifier inside the text field. Use a natural in-story form of address supported by the source, or omit direct address when uncertain.
- Emit exactly one scene object for every supplied selected scene, in the supplied order.
- Use each supplied exact Cxxx anchor once. Never output a slot that was not supplied.
- Key visuals are intentionally excluded. Never output a Key Visual anchor.
- Never omit or skip a supplied scene object. Its entries array may be empty only when the exact illustrated moment should remain silent or has no suitable visible or narratively present character.
- A line must belong to a character visible or narratively present in that scene.
- Emit at most two dialogue/thought entries per scene. This is a hard limit.
- Prefer one entry: the illustrated speaker's single most relevant utterance or thought.
- For each selected scene, search its upper_window first and choose the closest suitable dialogue or thought above the insertion slot.
- Use lower_window only when upper_window has no suitable entry, and then choose the closest suitable entry below the slot.
- Never cross the supplied window boundaries. Text beyond a neighboring illustration belongs to another illustration and is forbidden.
- If neither bounded window contains a suitable source line, add one short context-faithful thought or reaction only when it is natural and supported. Otherwise keep the scene object with entries: [].
- Use two entries only for one immediate exchange: one utterance followed by one direct reply.
- Never continue to a third turn, never output an A-B-A exchange, and never split one utterance across multiple entries.
- If the source contains a longer conversation, select only the one line or single two-entry exchange that best matches the exact illustrated moment.
- Do not output explanations, alternatives, confidence scores, or unrequested Scene blocks.
- Output only the required JSON object, without Markdown fences or explanations.
